# ทดสอบเมือง 2,000 คน

ฐานโปรแกรม: main หลัง PR78, b0bf5dcf8997af216a54e7aa033ce92ee86b98e7
งานนี้เพิ่มการทดสอบเท่านั้น ไม่เพิ่มเพดานธุรกิจ/กำลังผลิต/เงินหรือแก้กฎย้ายออกในโปรแกรมเกม

## เมืองทดสอบ
- 666 ครอบครัวแบบ3คน +2ครัวเรือนคนเดียว =2,000คน /668ครัวเรือน
- แรงงานเริ่มต้น1,334คน
- โรงงาน64แห่ง ระดับ9 รวม768ตำแหน่ง ตามเพดานปัจจุบัน ไม่สร้างบริษัทเกิน64เพื่อให้ผลผ่าน
- เงินทุนเริ่มต้นและสัญญาน้ำไฟภายนอกเป็นค่าที่จัดเตรียมสำหรับทดสอบ ไม่ใช่การจำลองเมืองเติบโตตามธรรมชาติ และไม่ได้ใส่ลงในเกมจริง

## สิ่งที่ตรวจพบ
สมมติฐานว่าเมืองนี้ต้องรักษาประชากร2,000คนตลอด31วันไม่ผ่าน: เมื่อสิ้นเดือนมี134ครัวเรือนย้ายออก รวม402คน เหลือ1,598คน เป็นผลกฎว่างงาน/ไม่มีค่าจ้างเดิมและข้อจำกัดตำแหน่งงาน ไม่ใช่หลักฐานว่าโปรแกรมรองรับจำนวน2,000ไม่ได้

จึงแยกการตรวจความถูกต้องจากความยั่งยืนของเศรษฐกิจ:
- ตรวจเริ่มต้น2,000คนจริง ไม่ใช่คูณตัวเลขแสดงผล
- จำลอง31วันและรอบจ่ายเงินเดือน เปรียบเทียบสองเมืองที่เริ่มจากเซฟเดียวกันทุกวัน
- ตรวจผลรวมบัญชี0 บัญชีภายในไม่ติดลบ ตัวตนคนที่ยังอยู่คงเดิม คนย้ายออกต้องมีรายการคืนเงินออกและยอดกระเป๋า0อย่างถูกต้อง
- ไม่ข้ามการย้ายออก ไม่เพิ่มตำแหน่งงาน ไม่ปิดกฎเดิมเพื่อฝืนรักษา2,000คน
- เซฟ/โหลดทั้งเมืองและนาฬิกาสวนต้องตรงกันครบ
- เพิ่มกรณีบราวเซอร์จริงผ่านหน้าจอLoad/Save บนจอมือถือจำลอง390px และเก็บ120ช่วงเฟรมขณะเล่น1x; ผลCIต้องตรวจแยก ไม่ถือว่าเขียนสคริปต์แล้วผ่าน

## ผลวัดฝั่งคำนวณรอบแรก
เครื่องCloud ไม่ใช่โทรศัพท์จริง:
- ช่วงที่เริ่มวันด้วย2,000คน21รอบ ค่ากลางประมาณ65.1ms/วันจำลอง
- รวม31รอบ: ค่ากลาง59.4ms, P95 112.7ms, สูงสุด125.4ms
- Serialize+ตรวจโหลดเซสชันประมาณ126.4ms, ขนาด577,047bytes หลังจำลอง
- ผลสุดท้าย1,598คน /534ครัวเรือน /แรงงาน1,066คน /มีงาน768คน /ว่างงาน298คน

ตัวเลขเหล่านี้ไม่ใช่FPS ไม่รวมประสิทธิภาพโทรศัพท์จริง และขึ้นกับเครื่องทดสอบ ต้องรายงานผลวัดเฟรมบราวเซอร์แยก ไม่สรุปว่า2,000คนลื่นบนมือถือทุกเครื่อง

## ข้อสรุปขอบเขต
ความถูกต้องของข้อมูลกับความสามารถให้เมืองเติบโตถึงและรักษา2,000คนเป็นคนละประเด็น การแก้ความจุธุรกิจ/สาธารณูปโภคต้องออกแบบและทดสอบเศรษฐกิจต่างหาก ไม่รวมในงานทดสอบนี้
