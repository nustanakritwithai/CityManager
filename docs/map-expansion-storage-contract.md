# Northern land expansion

The original 24×24 parcels keep IDs 0–575, x/z coordinates, terrain, seed, and all existing entities. Four rows are appended as IDs 576–671 north of row zero, producing a 24×28 land-only city. The original terrain inside the old buildable square is unchanged; the previously decorative north strip is prepared as flat buildable ground, with a short blend outside it. No ports or water tiles are introduced.

An existing server city is decoded and fully validated under its own version before in-memory expansion. No write occurs on load. New cells are empty, and `fertility-2` appends deterministic values without advancing the city RNG. Existing money, journals, accounts, entity IDs, positions, market identity, and park state are retained. Original bytes remain unchanged in the server until an ordinary user save. A separate v26 / `chain-21` envelope wraps v25 and explicitly identifies `north-24x28`; older readers reject it instead of treating expanded data as an old map. Unknown layouts, old-version oversized grids, invalid fertility and invalid topology fail closed.

Road topology v2 uses radix 672 and cardinal directions, with validated v1 junctions and arrows translated on migration. This avoids numeric-delta discontinuities at the north seam. Runtime traffic, bus and rail use actual mapped cardinal neighbors. Rail sessions are validated against their old city first, then rebound without changing the clock, passengers, network, or IDs; the next save binds the migrated session to the new exact city payload.

The older, inactive aggregate `TrafficClock`/`TrafficBridge` parcel-zone protocol is not a persisted City format or the enabled worker-game traffic. Its numeric 576-based namespace would collide with new cells; it fails closed if requested for an expanded map. Enabling that dormant subsystem later requires its own versioned namespace and compatibility tests.

Verification must cover populated legacy and expanded server-save round trips, market/park/rail session preservation, construction and routes across the seam, terrain, desktop and touch picking, minimap, camera, and performance. The scoped workflow keeps build, asset verification and the server-backed browser smoke mandatory; browser fixtures use synthetic accounts and an isolated in-memory store, not production data. No browser-local city saving is introduced.
