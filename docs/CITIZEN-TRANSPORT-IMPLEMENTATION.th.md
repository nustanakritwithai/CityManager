# ระบบเดินทางรายบุคคล: สถานะการพัฒนา

สถานะ: foundation ใน feature branch เท่านั้น ยังไม่เชื่อมกับ renderer หรือ save ของผู้เล่น

## ขอบเขตที่ผู้ใช้อนุมัติ

- ใช้ตัวตนประชากรเดิม ทุกการเดินทางมีคนจริง ไม่สร้างรถตกแต่งแทนจำนวนคน
- คนในครอบครัวเดียวกัน เส้นทางและเวลาเข้ากัน นั่งรถด้วยกันได้
- ไม่ลดจำนวนผู้เดินทางเพื่อแก้ประสิทธิภาพ ลดรายละเอียดภาพแทน
- รถต้องรอคิวและเคารพทางแยก ไม่มีการขับทะลุรถคันหน้า
- ใช้ game clock เดียวกับกิจกรรมและเศรษฐกิจ ไม่ใช้เวลาท้องฟ้าตกแต่ง
- เซฟเก่าต้องเปิดได้ และรักษาเงิน งาน สินค้า และตัวตนแขก

## โค้ดส่วนแรก

- citizen-commutes.ts อ่านตัวตนจาก parkActivityCitizens ไม่สร้างประชากรใหม่ แปลงแรงงานแต่ละคนเป็นความต้องการเดินทาง ใช้ directed BFS ผ่านทุก frontage ไม่บังคับเชื่อม gateway สำหรับการเดินทางภายในเมือง
- citizen-trips.ts รวมรถเฉพาะครอบครัว จุดเริ่มและหน้าต่างเวลาเดียวกัน ผู้โดยสารลงตามเส้นทางจริงของคนขับ คนขับลงสุดท้าย ค่าทดลอง 4 ที่นั่งรวมคนขับ ปรับได้ ไม่มีเพดานจำนวนคน
- citizen-journey.ts เก็บสถานะ waiting/in-vehicle/arrived และ manifest รถ การเลื่อนเวลาอย่างเดียวไม่ทำให้ถึงปลายทาง ต้องได้รับ road movement ที่อนุมัติ เซฟทดสอบของโมดูลตรวจจำนวนและตำแหน่งคนตรงกับรถ
- citizen-return.ts วางแผนกลับด้วยรถคันเดิมจากตำแหน่งที่จอด รับสมาชิกตามจุดงาน คำนวณเส้นทางขากลับใหม่ ไม่กลับลำลูกศรถนนทางเดียวโดยตรง

## ยังไม่เสร็จ / ห้ามอ้างว่าใช้งานจริงแล้ว

1. เชื่อม persistent fleet ข้ามวันกับเมืองจริง (state machine ขากลับระดับโมดูลทำแล้ว รวมรอสมาชิกพร้อม รับตามจุด และเซฟระหว่างรับกลับ)
2. ขยาย cell/lane admission ที่ทดสอบแล้วเป็นการเคลื่อนไหวต่อเนื่อง พร้อม spacing และ reroute diagnostics
3. clock pacing ที่ยังคงจังหวะเศรษฐกิจเดิม ต้องวัดกับ 1 วันต่อวินาทีปัจจุบันก่อนกำหนดค่า
4. renderer แบบจำนวนมาก และกำจัดการแสดงตัวคนซ้ำกับ park activity
5. atomic save envelope และ migration แบบเก็บต้นฉบับ ห้ามนำ snapshot ของโมดูลไปแทนเซฟเมืองโดยตรง
6. UI จำนวนผู้โดยสาร งานที่กำลังทำ เหตุผลรอ/ไปไม่ถึง และตำแหน่งรถ
7. การเชื่อมเวลาเข้าเวร การผลิต และรายได้ โดยไม่หัก/จ่ายซ้ำกับเศรษฐกิจเดิม
8. ทดสอบ browser ด้วยประชากร 2,000 และแยกจำนวนรถพร้อมกันจริง ไม่เทียบกับ 40 รถตกแต่งเดิม

## ข้อจำกัดที่ต้องแก้ก่อนเปิดใช้

- Identity เดิมเป็น household member slots ไม่มีอายุ/ใบขับขี่ การทดลองนี้ให้เฉพาะ employed slots ขับได้ ไม่ตีความ dependent เป็นเด็กโดยอัตโนมัติ
- ขากลับขยับได้ใน journey module เมื่อ road solver อนุมัติ ยังไม่เชื่อม renderer หรือเพิ่มทรัพย์สินในเมือง
- Road queue module ควบคุม occupancy แบบช่อง/เลนและจองแยกแล้ว ยังต้องเชื่อม quantum กับ canonical clock และ animation ก่อนเปิดจริง
- ใช้ prepareJourneyFrame ทำ index ต่อ quantum แล้ว ทดสอบ 2,000 รถเดี่ยวในข้อมูลได้ แต่ไม่ใช่ผล FPS ของ browser
- Snapshot validator ของโมดูลไม่ใช่ server security boundary

## ขั้นรับกลับและคิวถนน

เพิ่ม beginReturnRide ใช้รถคันเดิม รอสมาชิกพร้อม ลงทะเบียนคนที่ยังรอ ณ ที่ทำงาน และรับเมื่อรถไปถึงเท่านั้น เพิ่ม road queue ที่รักษารถทุกคันในคิว รองรับ 2 เลนทางเดียว ไม่อนุญาต timeout เพื่อขับทะลุ และตรวจ occupancy คู่กับ journey snapshot ทดสอบถนนถูกลบ/สร้างคืนและทางแยกตัดกัน ระดับข้อมูลยังไม่ใช่การเล่นจริงบนเว็บ

## Renderer แยกสำหรับตรวจประสิทธิภาพ

scene-citizen-vehicles.ts ใช้ hardware instancing 6 กลุ่มสี โมเดล 24 triangles ต่อคัน ไม่มีจำนวนสูงสุด ไม่มี entity ต่อรถ ใช้เฉพาะ snapshot ของตำแหน่งรถจริงที่ผ่าน admission ตัวทดสอบ renderer สร้างตำแหน่งสังเคราะห์ 2,000 คันแยกต่างหากเพื่อวัด GPU ไม่ใช่ผลทดสอบเมืองเต็ม ระบบยังไม่เปิดในเกมหลักและยังรอผล browser CI

## Clock, fleet และ save codec ที่เพิ่มในขั้นถัดมา

citizen-transport-runtime.ts ใช้นาทีเกมต่อเนื่องซ้ำแล้วไม่ขยับรถซ้ำ รักษา fleet ID ข้ามวันและคงรถ/ผู้โดยสารที่ยังติดอยู่จากวันก่อน citizen-life-session.ts เชื่อม observer กับ park runtime โดยค่า default เดิมไม่เปลี่ยน และป้องกันคนที่ยังอยู่ที่งาน/อยู่บนรถไปปรากฏในสวนพร้อมกัน

Save codec ทดลองรวม citySession และ transport ใน envelope เดียว และตรวจตัวตนจริง ตำแหน่งรถ คิว และเวลาร่วมกัน ยังไม่เขียนทับ slot เซฟผู้เล่นเดิม การเปลี่ยนจำนวนสมาชิกบางคนขณะอยู่ระหว่างทางยังต้องมี reconciliation เพิ่มก่อนเปิดใช้จริง ส่วนการย้ายออกทั้งครอบครัวรองรับเมื่อเปลี่ยนวัน

ผล renderer แยกที่ head 22919c86: 2,000 ตำแหน่งรถสังเคราะห์, 6 draw calls, 24 triangles ต่อคัน, median/P95 16.7 ms ใน CI Edge 1280×800 เป็นผล isolated rendering ไม่ใช่เมืองเต็มหรือมือถือจริง หลักฐาน Actions run 40866679784 artifact 12894570815

เพิ่ม fixture CityView จริงพร้อมประชากร 2,000 และงานจริงจากตัวจำลองเดิม (จำนวนรถตามคนมีงานและ carpool ไม่ใช่บังคับ 2,000 รถ) เพื่อทดสอบ renderer + journey + queue + save ร่วมกัน การทดสอบนี้ใช้หนึ่งนาทีเกมต่อ frame และ low quality บน viewport มือถือ แยกจากจังหวะ production ที่ยังไม่เปลี่ยน

## ชุด 1 — วันที่ 29 ตุลาคม 2026: เที่ยวจริงก่อนเชื่อมเกมหลัก

อัปเดตฐานจาก main ที่มี PR #89 แล้ว โดยไม่แตะงานเซฟ v23 ที่ยังค้างใน worktree เดิม และไม่รวมงานเวลา 6 วินาทีซึ่งส่งให้ agent อีกงานหนึ่ง

- Runtime ใช้ carpool แบบครอบครัวเดียวกัน ปลายทางเดียวกันก่อน ส่วน planner เดิมยังรองรับ prefix routes สำหรับขั้นถัดไป
- กระจายเวลาออกภายในหน้าต่าง 07:00–07:30 ด้วยค่าที่คำนวณซ้ำได้จากครอบครัว/ปลายทาง/วัน ไม่ใช้ random ตาม frame และไม่เปลี่ยนจำนวนคน
- เปิดสถานะหลังช่วงออกทำงานแล้วไม่ย้อนสร้างเที่ยวเช้าใหม่ ใช้เหตุผล missed-departure และวางแผนวันถัดไปตามปกติ
- รวมครู/อาจารย์ที่มีการจัดสรรจริงเข้ากับ roster โดยใช้ช่องแรงงานว่าง ไม่เพิ่มประชากรหรือคนทำงานซ้ำ
- ทดสอบรถที่ถูกปิดถนนข้ามเที่ยงคืน คง ID รถและคนเดิม เมื่อทางกลับมาใช้ได้จึงไปถึงและกลับบ้าน ไม่สร้างเที่ยวเช้าซ้อน
- ทดสอบป้อนนาทีเกมที่เทียบเท่าวันละ 6 วินาทีด้วย 20/30/60 frames ต่อวินาที ได้ snapshot การเดินทางและเศรษฐกิจตรงกัน ไม่ใช่การอ้าง FPS จริง

ผลเฉพาะส่วนในเครื่อง: citizen modules + park activity/runtime + education session 63 tests PASS; TypeScript PASS.

ยังไม่เปิด renderer หรือ storage ของระบบรถใน production งานชุด 2–4 ยังแยกไว้ตามแผน รวมการเปลี่ยนจำนวนสมาชิกบางคนกลางเที่ยวซึ่ง runtime ยังปฏิเสธแทนการเดาตัวตน การย้ายบ้าน/ที่ทำงานระหว่างเที่ยวและ reroute ต้องมีนโยบายก่อนเปิดเกมจริง ห้ามนำโมดูลที่ผ่าน unit tests ไปอ้างว่า PR84 ทั้งชุดพร้อมเผยแพร่.
