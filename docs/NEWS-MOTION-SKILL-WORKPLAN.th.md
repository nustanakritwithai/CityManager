# แผนการทำงาน สกิล `map-story-motion`

แผนนี้ลงรายละเอียดงานจาก [แผนสกิล](NEWS-MOTION-SKILL-PLAN.th.md) เป็นงานย่อยที่ลงมือได้ทันที

## ค่าเริ่มต้นที่ใช้ระหว่างรอคำตอบ
เรื่องที่ยังไม่ได้ตัดสินใจในข้อ 14 ของแผนสกิล ใช้ค่าต่อไปนี้ไปก่อน เปลี่ยนภายหลังได้โดยไม่ต้องรื้องาน
| เรื่อง | ค่าเริ่มต้น | ถ้าเปลี่ยนจะกระทบ |
|---|---|---|
| ที่เก็บ | repo ใหม่ `map-story-motion` | ย้ายโฟลเดอร์ได้ทั้งก้อน |
| ธีมแรก | `neon-history` (ดาวเทียม + เรืองแสง) | สลับลำดับเฟส 1 กับ 3 |
| เสียง | ซับอย่างเดียว | เฟส 6 ทำเร็วขึ้น |
| ภาพ AI | ไม่ใช้ในรุ่นแรก | เพิ่มงาน 6.3 |
| เชิงพาณิชย์ | สมมติว่าใช่ (เลือกแต่แหล่งที่ใช้เชิงพาณิชย์ได้) | ไม่กระทบ |

## ภาพรวมเวลา
หน่วยเป็น "รอบทำงาน" (session ละประมาณครึ่งวัน กับ Claude Code)

| สัปดาห์ | เฟส | ผลลัพธ์ที่ผู้ใช้เห็น | จุดตรวจ |
|---|---|---|---|
| 1 | 0 ตั้งโครง + สคีมา | ไฟล์ตัวอย่าง story.yaml 2 เรื่อง + ภาพนิ่งแผนที่ | ✅ ผู้ใช้ตรวจสคีมา |
| 1–2 | 1 แผนที่ + กล้อง + ข้อความ | **คลิปแรก 30 วิ** สไตล์ภาพ 1 (ยังไม่มีการ์ด) | ✅ ผู้ใช้ตรวจสไตล์ |
| 2–3 | 2 การ์ดและภาพบนแผนที่ | คลิปสยาม/เขมรเต็ม 60 วิ (**MVP**) | ✅ ผู้ใช้ลองใช้จริง |
| 3–4 | 3 แผนที่วาด | คลิปพังงาสไตล์ storybook | ✅ |
| 4–5 | 4 ชุดภาพประกอบ | ฉากเวกเตอร์ + ไอคอน + ภาพปก | ✅ |
| 5 | 5 จากบทความถึงคลิป | ใส่บทความดิบแล้วได้คลิป | ✅ |
| 6 | 6 เสียง + ธีมเพิ่ม | คลิปพร้อมโพสต์ | ✅ |
| 6–7 | 7 ทดสอบ + เผยแพร่ | สกิลติดตั้งได้ + คู่มือ | ✅ ส่งมอบ |

รวมประมาณ 25–30 รอบทำงาน แต่ละเฟสจบด้วยคลิป/ภาพให้ดูจริง ไม่มีเฟสที่ส่งแต่โค้ด

## ความเสี่ยงและทางแก้
| ความเสี่ยง | ทางแก้ |
|---|---|
| tile ดาวเทียมโหลดช้า/โดนจำกัด ทำให้เรนเดอร์นาน | แคชลงดิสก์, ดาวน์โหลดล่วงหน้าเฉพาะพื้นที่ในเรื่อง, สำรองด้วย Blue Marble |
| เฟรมจับก่อน tile โหลดเสร็จ (ภาพเบลอ/ว่าง) | รอ `idle` ทุกเฟรม + ตรวจเฟรมว่างอัตโนมัติ |
| ภาพประกอบเวกเตอร์ดูไม่ถึงระดับตัวอย่าง | ล็อกสไตล์กับผู้ใช้ที่งาน 4.1 ก่อนทำจำนวนมาก |
| อาณาเขตโบราณผิด/ถูกวิจารณ์ | บังคับ `ref` + ป้าย "แนวโดยประมาณ" + จุดยืนยันภาพนิ่ง |
| ฟอนต์ไทยในหัวข้อหนาๆ สระทับกัน | ทดสอบชุดคำยาก (ที่, ปั้น, ญี่ปุ่น, กั๊ก) ในเฟส 1.6 |
| สกิลซับซ้อนจน Claude ใช้ผิด | ให้ Claude ทำงานผ่าน story.yaml อย่างเดียว ทุกอย่างอื่นเป็นสคริปต์ + validate จับผิดก่อนเรนเดอร์ |

## สิ่งที่ต้องได้จากผู้ใช้ (เรียงตามเวลาที่ต้องใช้)
1. ก่อนเริ่ม: คำตอบ 5 ข้อในแผนสกิล (ไม่ตอบ = ใช้ค่าเริ่มต้นด้านบน)
2. ก่อนเฟส 2 จบ: หัวข้อเรื่องจริง 2–3 เรื่องที่อยากทำ (ใช้เป็นเคสทดสอบ)
3. ก่อนเฟส 4: อนุมัติแผ่นอ้างอิงสไตล์ภาพประกอบ
4. ก่อนเฟส 6: ไฟล์เสียงพากย์ตัวอย่าง หรือเลือกผู้ให้บริการ TTS / ภาพ AI
