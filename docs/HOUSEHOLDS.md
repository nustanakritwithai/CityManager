# ครัวเรือนและสถานประกอบการ รุ่น 2

งานบน `feat/household-capacity` เริ่มจากรุ่นเผยแพร่ `504f16a30199cd6fd47be0d98e1b20d26aed2c0e` เป็น micro release สำหรับ **ครัวเรือนแต่ละหน่วยและสถานประกอบการแต่ละแห่ง** ยังเป็นงานสำหรับ draft PR ไม่ได้ merge หรือเผยแพร่ ไม่มี cohort รวมแทนครัวเรือน ไม่มี agent รายบุคคล และไม่มี AI integration

## หน่วยข้อมูลและบ้าน

ครัวเรือนมี ID และกระเป๋าเงินของตัวเอง ที่อยู่เป็นเพียงการอ้างอิงอาคารและอาจเป็น `null` เมื่อไม่มีบ้าน จึงไม่ทำลายเงินหรือเอกลักษณ์ของครัวเรือนเมื่อย้ายที่อยู่ สมาชิกเก็บเป็นจำนวนเต็ม โดย `members = workforce + dependents`; workforce คือแรงงานที่มีได้ ส่วนแรงงานที่ได้รับงานจริงนับจาก allocation อีกชั้นหนึ่ง

| Profile | สมาชิก | กำลังแรงงาน | ผู้พึ่งพิง |
|---|---:|---:|---:|
| `single-worker` | 1 | 1 | 0 |
| `family` | 3 | 2 | 1 |
| `legacy-worker` จาก v1 | 1 | 1 | 0 |

ค่า `legacy-worker` เป็น **สมมติฐานขั้นต่ำเพื่อเริ่มข้อมูลที่ v1 ไม่เคยเก็บ** ไม่ใช่จำนวนประชากรจริงในอดีต ไม่สร้างย้อนหลังเป็นการเกิดหรือย้ายเข้า UI ต้องระบุที่มานี้ และยอดเมืองแยกจำนวนคน ครัวเรือน กำลังแรงงาน ผู้พึ่งพิง และแรงงานมีงานให้ชัดเจน

บ้านชนิด `cottage` ใช้กติกา `household-1` และตรวจความจุสองด้านพร้อมกัน:

| ระดับ | จำนวนครัวเรือนสูงสุด | จำนวนสมาชิกสูงสุด |
|---|---:|---:|
| 1 | 1 | 4 |
| 2 | 2 | 8 |
| 3 | 3 | 12 |

นี่คือค่าดุลเกมที่เสนอสำหรับโครงการนี้ **ไม่ใช่ข้อเท็จจริงหรือสูตร CSII** การเพิ่มระดับขยายที่ว่างเท่านั้น ไม่คูณคนที่พักอยู่ บ้าน R ใหม่เริ่มว่างและรับผู้อยู่อาศัยได้เร็วสุดใน tick วันถัดไป

การรับเข้าแต่ละวันต้องมีถนนเชื่อม น้ำ/ไฟ ที่ว่างทั้งสองด้าน และงานว่างที่มีเงินสำรองค่าจ้างกับรายได้พอค่าของจำเป็น/ค่าเช่า ให้แรงงานเดิมที่ว่างงานและครัวเรือนไร้บ้านได้รับการจัดการก่อนรับใหม่ รับไม่เกินหนึ่งครัวเรือนต่อวัน เลือก family เมื่อมีงานรองรับอย่างน้อยสองตำแหน่ง หรือ single-worker เมื่อมีหนึ่งตำแหน่ง สิทธิยกเว้นเงื่อนไขงานของสองครัวเรือนแรกเป็น **ยอดรับเข้าตลอดอายุเมือง** ไม่รีเซ็ตเมื่อรื้อบ้าน เงินติดตัว 150,000 สตางค์มาจาก outside หนึ่งครั้งต่อครัวเรือน ไม่ใช่ต่อสมาชิก

รื้อบ้านแล้วครัวเรือนเดิมกลายเป็นไม่มีที่อยู่และหยุด allocation ที่ได้รับผล แต่ยังมี ID สมาชิก เงิน และสิทธิค่าจ้างที่ทำแล้ว การจัดบ้านใหม่แต่ละวันเกิดก่อนรับผู้ย้ายเข้าใหม่ การย้ายบ้านไม่โอนหรือสร้างเงิน ไม่เพิ่มคน ยังไม่มีแบบจำลองเกิด ตาย หรือย้ายออกจากเมืองใน release นี้

## แรงงานและเศรษฐกิจที่คงไว้

`EmploymentAllocation` เป็นข้อมูลการจ้างงานหลัก: ครัวเรือนหนึ่งแบ่งแรงงานจำนวนเต็มไปหลายบริษัทได้ แต่ยอดรวมต้องไม่เกิน workforce ของตัวเอง บริษัทรับได้ตามตำแหน่งและเงินค่าจ้างจริง งานเดิมที่ยังถูกต้องได้สิทธิก่อนจัดงานว่างใหม่ ลำดับคงที่ช่วยให้ผลจำลองซ้ำได้ ไม่มี person agent ซ้ำอยู่หลายแห่ง

อาชีพเริ่มต้นเป็น manufacturing สำหรับ I และ retail สำหรับ C ระดับ `entry` เท่านั้น ค่าจ้างเดิมคงที่และสะสมเป็น **employee-days**: ครัวเรือนที่ส่งสองคนทำหนึ่งวันนับสอง employee-days จึงอาจมากกว่าจำนวนวันปฏิทิน จ่ายตามจำนวนนี้ในรอบ 30 วัน เงินค่าจ้างที่จองแล้วไม่ใช้ซื้อของหรือขยายอาคาร ไม่เพิ่มระบบเลื่อนขั้นหรือเปลี่ยนอัตราค่าจ้างย้อนหลัง

ยังใช้สินค้านามธรรมหนึ่งตะกร้าต่อ **ครัวเรือนต่อวัน** ราคา ค่าเช่า และภาษีเดิม สมาชิกไม่คูณ stock, ประวัติ หรือยอดบริโภคย้อนหลัง การสอบทานเงิน/สินค้าเดิมยังจำเป็น แต่ release นี้ไม่ได้อ้างว่าเป็นบัญชีธุรกิจครบรูปแบบ วงจรชีวิตครบถ้วน หรือรองรับประชากรระดับล้านคน

## Save v2 และการกู้คืน

- เซฟใหม่อยู่ที่ `citymanager.save.v2`; `citymanager.save.v1` เดิมคงอยู่ โหลด v2 ก่อนเมื่อมี มิฉะนั้นอ่าน v1 เพื่อนำเข้า **ในหน่วยความจำเท่านั้น** ไม่ auto-save จากการโหลด
- ปุ่ม Game **นำเข้าเซฟ v1** (`#load-legacy`) เลือกต้นฉบับโดยตรง และ **กู้คืนสำเนา v1** (`#load-backup`) อ่านสำเนาที่มีอยู่ การอ่าน v2 ที่เสียหายไม่แอบแทนด้วยเมืองเก่าอีกเมืองหนึ่ง
- เมื่อผู้ใช้กด Save หลังนำเข้า จะเก็บ raw v1 แบบเดิมตรงตัวก่อนเขียน v2 ลง `citymanager.backup.v1` ถ้ามีต้นฉบับต่างกันจึงใช้ `.1` ถึง `.7` สำเนาเดิมไม่ถูกทับ และต้นฉบับเดิมซ้ำใช้ slot เดิม
- ถ้าเขียน backup ไม่ได้หรือครบแปดต้นฉบับต่างกัน จะไม่เขียนทับช่อง v2 ถ้าสำรองสำเร็จแต่ v2 เขียนไม่ผ่านเพราะ quota เซฟ v2 เดิมยังอยู่และ backup ที่เขียนแล้วใช้กู้คืนได้ ไม่มีการลบข้อมูลอื่นเพื่อคืนพื้นที่
- นำเข้า v1 ต้องผ่านตัวตรวจเดิมก่อน แปลงองค์ประกอบครัวเรือนตามสมมติฐาน 1/1/0 และงานเดิมเป็น allocation หนึ่งแรงงาน รักษาเงิน journal สินค้า สิทธิค่าจ้าง ID, seed, RNG และ tick ไม่สร้าง arrival หรือย้อนหลังจำนวนคน

```sh
npm test
npm run assets:verify
npm run build
npm run preview
```
