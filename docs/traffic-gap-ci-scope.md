# Reviewed bumper-gap and shared right-of-way acceptance

The `traffic-gap` route requires the exact reviewed source diff and explicit paths on the PR merge-base/head or push before/after range. Empty, unknown, mixed-feature and changed source hashes use the default full route.

Required coverage:
- Existing traffic clock/routing/fleet/network/demand/queue/poses and game/worker/layer/modal/fallback tests, plus explicit physical-spacing regressions.
- The strict bypass improvement preflight (same demand and roads, equal 20-step warmup on both paths for acceleration and safe corner traversal) and bounded stress/capture/worker benchmarks, with unchanged budgets.
- Actual built game entered through the isolated server ACK fixture: real Worker frames, busy actual-render-frame clearance and stable admitted IDs, native pause/resume and OFF/ON, one-attempt worker fault fallback, real server save/reload and no browser city writes. Synthetic fixture screenshots use the existing health-checked readback path. No live accounts or saved cities.
- Mandatory complete server-save acceptance, typecheck and production build; deploy uses that same run's built artifact.

The old full/core/extended and default/fault browser entrypoints assume localStorage city loading and obsolete recovery/backup ownership. They are **not run and not reported passed** on this exact route. Their relevant traffic assertions are retained in the unit/worker/preflight tests and authenticated browser helper. The unrelated dense FPS matrix is not claimed. Unknown or mixed changes retain the existing full job requirements; this is not a global deletion or general traffic exemption.

The legacy storage-utility autosave regression remains a utility test, not a claim that current gameplay writes browser saves. It requires current primary-first publication and both exact lossless copies. Actual gameplay durability is checked against the server transaction ACK.

The shared-right-of-way transition is a separate exact complete source-diff hash on its own base; it reuses the scoped traffic gate without broadening the earlier bumper-gap allowlist. Bus movement proposals now require live permission before advancing actual engine position or passenger events. **All active bus/car overlaps and every intrusion diagnostic fail**; the previously documented moving-bus exception is no longer accepted. Only engine `home` phase may omit a bus mesh, with the bus identity and facility count retained. Actual scene GPU counts, bus passenger ledger, service clock, movement counters and visible-car identities are recorded together. Focused real-engine tests additionally require hold/resume, continued global clock/timeouts, boarding/alighting exactly once, topology changes and conservation, plus worker-junction fairness and the atomic active-depot deletion guard. The short browser sample does not claim a full one-minute dwell/service cycle.


The browser runs a light real-bus fixture and a separate canonical 32-family bottleneck session. The latter reuses the preflight road layout with a bus route created through real depot/stop/line commands crossing its bottleneck, and is acknowledged only by the loopback mock service; the actual production Worker derives demand from the loaded city. It must show blocked/congested traffic before capture. No Worker input is overwritten, no long economic warmup is used, and the original light session is restored before the mandatory save failure/lifecycle cases.

Busy browser acceptance requires the same bus to be physically stationary while `heldDrive` and global service time advance, followed by a later movement grant and a changed actual position. Earlier aggregate grants cannot pass. The natural approach, hold and release sequence is longer than the original four-second light sample, so only this new busy phase has a 30-second bound; unrelated waits remain unchanged. A bounded 360-frame ring plus three compact hold/release event records preserves proof without unbounded telemetry or repeated large CDP transfers. A missing resume is a failure, not an accepted jam or a reason for blind retries.

Dense-grid acceptance reuses `trafficRightOfWayFixture` in the actual-layer tests and browser. Its route witness must encounter more than four conflict nodes. Mandatory deterministic L1/L2/L3 engine/layer cases cover feasible outbound, unchanged dwell and return with nonempty cars, physical clearance, stable live IDs and exact passenger conservation; saturated cases require finite admission work and no loss, not impossible progress through a fully occupied network. Off-route ingress, grant retention, physical downstream space, departure and topology reset remain focused regression requirements. The browser additionally loads the canonical L1 dense city through the isolated server ACK, samples actual Worker/rendered movement with the same strict verifier and captures the real scene. That short sample is explicitly **not** full-cycle or all-class browser coverage; it does not replace the separate natural bottleneck hold/resume assertion.

The browser-only bottleneck seed uses a legal depot at cell 320 beside conflict 296; the original depot 270 seed remains the long integration fixture. Roads, households, businesses, stops and traffic demand are unchanged. This removes untested approach travel from the short browser window after CI measured only 6.76 physical seconds in 30.4 wall seconds at 960×640. A focused actual-layer regression reproduces that low render cadence without changing production clocks and still requires prior drive, observed congestion, a real held bus and later physical resume. Browser assertions and 30-second deadline remain unchanged.
