# เซฟเก่าเมื่อเพิ่มการเกษตรและตลาดพืชผล

candidate ที่ยังไม่ Merge/เผยแพร่ ใช้รุ่นข้อมูล `4 / agriculture-1` เพิ่มวัตถุดิบพืชผล ฟาร์ม และตลาดที่ครัวเรือนเป็นเจ้าของ โดยใช้กระเป๋าเงิน ประชากร แรงงาน และประวัติเดิมต่อไป เอกสารนี้อธิบายการแปลงข้อมูลและการกู้คืน ไม่ใช่การรับรองว่าเซฟใหม่หรือหน้าเว็บผ่าน QA ครบแล้ว

## ตรวจรุ่นเก่าก่อนแปลง

ตัวอ่าน `src/legacy-v3.ts` แยกจากตัวจำลองใหม่และไม่มี import ไปยัง agriculture/labor ปัจจุบัน ใช้ชนิดข้อมูลและเงื่อนไขตรวจ `3 / worker-1` ที่ตรึงจาก commit ที่เผยแพร่ `4f3c6a399b18675242b4ad077af2f52a25d9198c` โดยตรง รวมข้อจำกัดความจุบ้าน/กิจการ กลุ่มความสามารถที่ไม่ซ้ำคน สิทธิค่าจ้างค้างจ่าย และการกระทบยอดเงินกับสินค้าจาก journal

การโหลด v1 และ v2 ยังผ่านตัวอ่าน frozen ของรุ่นตนก่อนตามลำดับการแปลง ข้อมูลเก่าที่เสียจะถูกปฏิเสธ ไม่ใช้สูตรเกษตรใหม่มาซ่อมยอดเดิมให้ผ่าน ตัวอ่านไม่เดิน tick ไม่จัดสรรงาน ไม่ให้เงิน/สินค้า ไม่ใช้ RNG และไม่เขียน storage

## ส่วนที่ต้องคงเดิม

การแปลง v3 ต้องเก็บ IDs, ที่อยู่, จำนวนครัวเรือน/สมาชิก/แรงงาน/ผู้พึ่งพิง, `workerSkills` ทั้งสามกลุ่ม, แหล่งที่มาของทักษะ, การจ้างงาน, กระเป๋าและยอดเงิน, finished inventory, money/goods journals, สิทธิค่าจ้าง, ประวัติการเข้าเมือง, tick, seed และ simulation RNG ไว้ตรงเดิม ไม่สันนิษฐานให้แรงงาน v3 กลับเป็นกลุ่มทั่วไปอีกครั้ง และไม่จ่ายค่าจ้างซ้ำระหว่างโหลด

เงินเดือนยังเป็นเงินจำนวนเต็มสตางค์และใช้บัญชีร่วมของแต่ละครัวเรือน ไม่สร้างบัญชีบุคคลหรือบัญชีเจ้าของตลาดย้อนหลังเพื่อให้เข้ากับรุ่นใหม่

## ส่วนที่เพิ่มอย่างเปิดเผย

- กำหนด schema เป็น 4 และกติกา `agriculture-1`
- เพิ่ม resource map ตาม seed ด้วยกติกาแยกจาก simulation RNG จึงไม่ใช้ลำดับสุ่มของการเติบโตเมืองขณะโหลด
- กิจการเดิมเริ่ม `cropInventory: 0`, `cropCost: 0` และ `productionTick` เท่ากับ tick เดิม
- ตั้ง `agricultureStartTick` เป็น tick เดิม counters ของพืชผลและ `cropLedger` เริ่มศูนย์/ว่าง รวม `consumed` สำหรับการบริโภคพืชผลโดยตรง
- กิจการเดิมเริ่ม `owner: null` และเมืองเริ่ม `ownerLabor: []` ไม่สร้างกรรมสิทธิ์หรือรายได้ผู้ประกอบอาชีพอิสระย้อนหลัง

finished generic goods ที่มีอยู่ไม่กลายเป็นพืชผล ไม่มี opening crop stock ไม่มีของขวัญวัตถุดิบ ไม่มีการเพิ่มฟาร์ม ตลาด ถนน หรือโซนให้เซฟเก่าเอง การขาดวัตถุดิบช่วงเปลี่ยนรุ่นเป็นสถานะจริงที่ต้องอธิบาย ผู้เล่นจึงค่อยกำหนดโซนฟาร์ม/ตลาดที่มีเงื่อนไขครบ

ประวัติการผลิต generic goods ก่อน `agricultureStartTick` ยังคงเป็นประวัติของกติกาเดิม การผลิตหลังจุดเปลี่ยนต้องมีวัตถุดิบและรายการใช้จริง ไม่ย้อนสร้าง crop journal เพื่ออ้างว่าการผลิตเก่าใช้พืชผลแล้ว

พืชผลรุ่นนี้ใช้ได้ทั้งเป็นวัตถุดิบโรงงานและเป็นตะกร้าบริโภคโดยตรงจากตลาด แต่ความต้องการครัวเรือนยังเป็นหนึ่งตะกร้ารวมต่อวัน: พืชผลหนึ่งหน่วย **หรือ** generic goods หนึ่งหน่วย ไม่ได้เพิ่มความต้องการย้อนหลัง และไม่เติม stock ให้ครัวเรือนเมื่อโหลด

## ช่องเซฟและ backup

| การใช้งาน | key / เมนู |
| --- | --- |
| เซฟรุ่นนี้ | `citymanager.save.v4` |
| เซฟแรงงานเดิม | `citymanager.save.v3` / นำเข้า v3 |
| เซฟความจุบ้านเดิม | `citymanager.save.v2` / นำเข้า v2 |
| เซฟต้นแบบเดิม | `citymanager.save.v1` / นำเข้า v1 |
| สำเนารุ่นเก่า | `citymanager.backup.v1`, `.v2`, `.v3` รุ่นละแปดช่อง |
| ตัวชี้สำเนาที่บันทึกล่าสุด | `citymanager.backup.latest` |

การอ่านปกติเลือก v4 → v3 → v2 → v1 โดยหยุดที่ช่องแรกที่มี bytes หากช่องนั้นเสีย จะแจ้งข้อผิดพลาดแทนการแอบเปิดอีกเมือง ผู้เล่นเลือกนำเข้าแต่ละรุ่นหรือเลือกกู้ backup ได้ชัดเจน

การโหลดไม่เขียนข้อมูลลงดิสก์ เมื่อกดบันทึกหลังนำเข้า เซฟเดิมจะถูกสำรองทั้ง bytes ก่อนเขียน v4 ช่องต้นฉบับ v1/v2/v3 ไม่ถูกลบหรือเขียนทับ สำเนาแต่ละรุ่นมี key หลักและ `.1` ถึง `.7` เก็บแบบไม่เปลี่ยนแปลง หาก raw เดิมมีสำเนาอยู่แล้ว จะใช้ช่องเดิมแม้มีช่องว่างก่อนหน้า ไม่สร้างสำเนาซ้ำ

ตัวชี้ latest เก็บเพียงชื่อช่อง backup ที่อนุญาต จึงกู้ตัวที่สำรองล่าสุดได้แม้สลับนำเข้า v1/v2/v3 หากตัวชี้หายหรือเสีย จะค้นด้วยลำดับรุ่นและช่องที่กำหนด ไม่มีการแต่ง timestamp ให้สำเนาเก่า และไม่ยอมให้ตัวชี้ชี้ออกไปยัง primary slot หรือ key อื่น

ถ้าแปดช่องของรุ่นที่นำเข้าเต็มและไม่มี raw เดิมตรงกัน จะยกเลิกก่อนเขียน primary การเขียน backup หรือตัวชี้ล้มเหลวจาก quota ก็ยกเลิกก่อนเขียน primary เช่นกัน หากสำรองสำเร็จแต่การเขียน primary ล้มเหลว primary เดิมและสำเนากู้คืนยังคงอยู่ ไม่ลบเซฟหรือสำเนาเก่าเพื่อขอพื้นที่เพิ่มเอง
