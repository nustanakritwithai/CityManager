## 4. ขั้นตอนที่เกมจะเรียก (ต้องกลับมาทำต่อได้ทุกจุด)
ทุกคำสั่งที่เปลี่ยนของหรือเครดิตมี **รหัสคำสั่งจากเกม** (UUID) ส่งซ้ำกี่ครั้งก็ต้องได้ผลเดิม ไม่ตัดหรือเพิ่มซ้ำ

### 4.1 ฝากของเข้าคลังตลาด (ของออกจากเมือง)
1. เกมย้ายของจากกิจการไปบัญชีพักในเซฟ สถานะ `pending` พร้อม `opId` แล้วบันทึกเซฟก่อนเรียกเซิร์ฟเวอร์
2. `POST deposit {opId, itemId, qty}` → เซิร์ฟเวอร์เพิ่มของเข้าคลังของ Guest ตอบ `{depositId, itemId, qty, seq}`
   ส่ง `opId` เดิมซ้ำต้องได้ `depositId` เดิม ถ้า `opId` เดิมแต่ `itemId`/`qty` ต่าง ตอบ error `op-mismatch`
3. เกมย้ายของจากบัญชีพักออกนอกเมือง สถานะ `confirmed` บันทึก `seq`
4. ถ้าผลตอบกลับหาย เกมถามซ้ำด้วย `opId` เดิมตอนเปิดใหม่ ต้องมีทางถามสถานะคำสั่งได้: `GET op/{opId}` → `{state: 'unknown'|'done', ...}`
   ถ้าเซิร์ฟเวอร์ตอบ `unknown` ผู้เล่นยกเลิกได้ และของกลับเข้ากิจการ

หลังของเข้าคลังแล้ว การตั้งขาย ซื้อบางส่วน ยกเลิก และหมดอายุ ใช้ระบบที่มีอยู่บนเซิร์ฟเวอร์ (คลังและการกันสต็อกเดิม)

### 4.2 รับของที่ซื้อเข้าเมือง (ของเข้าเมือง)
1. `GET receipts?state=ready` → `[{receiptId, itemId, qty, boughtAt}]` (ใบรับที่ยังไม่ส่งเข้าเมือง)
2. `POST receipts/{receiptId}/claim {claimId}` → เซิร์ฟเวอร์ล็อกใบรับไว้กับ `claimId` นี้ (สถานะ `claimed`) ส่งซ้ำต้องได้ผลเดิม
   ถ้า `claimId` อื่นมาขอใบเดียวกัน ตอบ `already-claimed` (กันเปิดหลายแท็บหรือหลายเครื่อง)
3. เกมเพิ่มของเข้ากิจการพร้อมรายการบัญชี `Market receipt #receiptId` แล้วบันทึกเซฟ ตัวตรวจเซฟจะปฏิเสธใบรับเดียวกันสองครั้งในเซฟเดียว
4. `POST receipts/{receiptId}/ack {claimId}` → สถานะ `delivered` ส่งซ้ำได้
5. ใบที่ `claimed` แต่ไม่ ack ภายในเวลาที่กำหนด (ให้เซิร์ฟเวอร์เสนอ เช่น 10 นาที) กลับเป็น `ready` และต้องเก็บประวัติไว้

### 4.3 ข้อมูลที่หน้าตลาดในเกมจะแสดง
- กระเป๋าเครดิต: `GET wallet` → `{credits, seq}`
- รายการขายของฉัน ประวัติซื้อและขาย ของในคลังตลาด ใบรับที่รอ: ใช้ endpoint ที่มีอยู่แล้ว ขอรูปแบบตอบกลับตามจริง

## 5. ข้อจำกัดที่ต้องรายงานตรง ๆ
- เซฟออฟไลน์: ถ้าผู้เล่นฝากของแล้วโหลดเซฟเก่า ของจะอยู่ทั้งในเมืองและในคลังตลาด
  - เกมเก็บ `seq` ล่าสุดที่เซิร์ฟเวอร์ยืนยันไว้ในเซฟ ถ้าเซิร์ฟเวอร์มี `seq` มากกว่าเซฟ เกมจะรู้ว่าเซฟเก่ากว่าตลาด
  - การกันโกงนี้ **ป้องกันการแก้เซฟหรือย้อนเซฟไม่ได้ทั้งหมด** ห้ามอ้างว่าใบรับหรือเลขลำดับแก้ปัญหานี้ได้ครบ
- ถ้ารับของแล้ว (`delivered`) แล้วผู้เล่นโหลดเซฟก่อนรับ ของนั้นจะหายจากเมือง เพราะเซิร์ฟเวอร์ส่งให้ครั้งเดียว

## 6. ที่ขอให้เอเจนต์บน VPS ทำ
1. ตรวจสถานะปัจจุบัน: PostgreSQL ชุดแยก `127.0.0.1:55432`, แอปตลาด, และทดสอบ 23/23 ยังผ่าน
2. เปลี่ยนสินค้า sandbox (wood/stone/iron) เป็น 6 itemId ในข้อ 2 หน่วยจำนวนเต็ม
3. เพิ่มหรือแมป endpoint ข้อ 4 ให้รับ `opId`/`claimId` แบบส่งซ้ำได้ ถ้า endpoint เดิมมีชื่อหรือรูปแบบต่างไป ให้ใช้ของเดิม แล้วเขียนตารางแมปใน `runbooks/` และส่งกลับมา
4. ทดสอบเพิ่ม: deposit ซ้ำ `opId` เดิม, deposit แล้วผลตอบกลับหาย, claim สองแท็บ, claim แล้วไม่ ack, ack ซ้ำ, ซื้อพร้อมกัน, คืนสต็อกหลังยกเลิก
5. CORS อนุญาตเฉพาะ `http://127.0.0.1:4173`, `http://localhost:5173` (เกมบนเครื่อง) ตอนนี้ และ `https://nustanakritwithai.github.io` เมื่อมี HTTPS สาธารณะที่ผู้ใช้อนุมัติแล้ว
   เกมบน GitHub Pages เป็น HTTPS จึงเรียก API แบบ HTTP บน loopback ไม่ได้ ช่วง sandbox ให้ทดสอบด้วยเกมที่ build บน VPS เดียวกัน
6. ส่งกลับมาที่ repo นี้ (issue หรือไฟล์ใน `docs/`) หรือให้ผู้ใช้แปะ: base URL, ตาราง endpoint จริง, รูปแบบ token, error codes, และผลทดสอบ จากนั้นฝั่งเกมจะทำ adapter, หน้าตลาด และเซฟ v10

## 7. นโยบายที่ยังไม่ตัดสิน (ห้ามเลือกแทนผู้ใช้)
