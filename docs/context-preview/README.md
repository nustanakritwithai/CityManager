Branch `feat/contextual-inspectors` เริ่มจากรุ่นสาธารณะบน `main` (`5c5f396`) และเตรียมส่ง **draft PR** งาน GUI รอบนี้ยังไม่ merge หรือ deploy ดู [หน้าบัญชีรวมแบบก่อนหน้า](../submenu-preview/phone-money.png) และ [ขอบเขตการออกแบบ](../CONTEXTUAL-GUI.md)

## ขอบเขตที่ต้องเห็นในภาพ

| หน้าที่เปิด | ข้อมูลที่ควรแสดง | ภาพหลังปรับ |
|---|---|---|
| บ้าน | อาคารที่เลือก ระดับ อายุ การเข้าถึง และครัวเรือนที่พักในบ้านนั้นจริง | [phone-house](phone-house.png), [ครัวเรือนในบ้าน](phone-house-members.png) |
| ครัวเรือน | กระเป๋าเงิน งาน บ้านปัจจุบัน การซื้อสินค้า และรายการที่ตรงกับบัญชีครัวเรือนนั้นเท่านั้น | [phone-household](phone-household.png) |
| ร้านค้า/โรงงาน | บริษัทในอาคารที่เลือก เงิน สต็อก แรงงาน ค่าจ้างจอง กำไร และรายการของบัญชีบริษัทนั้น | [phone-firm](phone-firm.png), [สต็อกและแรงงาน](phone-firm-stock.png) |
| ภาพรวมเมือง | จำนวนและยอดปัจจุบัน แยกจากเงินคลัง/สินค้าในช่วงไม่เกิน 30 วันล่าสุด | [phone-city](phone-city.png), [รายการรับ–จ่าย](phone-city-flows.png), [desktop-overview](desktop-overview.png), [phone-wide-city](phone-wide-city.png) |
| ความช่วยเหลือ | วิธีเล่น สมมติฐาน และเครดิตภาพ แยกจากข้อมูลสถานที่และเมือง | [phone-help](phone-help.png) |

ชื่อภาพเป็นรายการเตรียมหลักฐาน ผู้ทดสอบจะยืนยันชื่อไฟล์และเปิดตรวจภาพจริงหลัง capture; ลิงก์ภาพไม่ถือเป็นผลผ่านโดยตัวเอง

บ้าน A/B และบริษัท A/B ต้องแสดงข้อมูลเจ้าของที่ต่างกันอย่างถูกต้อง รายการเงิน/สินค้ากรองด้วย wallet ID แบบตรงตัวทั้งต้นทางและปลายทาง ไม่ใช้การจับข้อความบางส่วนและไม่ดึงบัญชีทั้งเมืองเข้าหน้ารายตัว ตัวเลข หน่วย วัน และ index ของรายการอ้างอิง journal จริง ไม่มีกราฟ รายได้ หรือประชากรรายบุคคลที่สร้างขึ้นเพื่อการแสดงผล หน่วยประชากรของต้นแบบยังเป็น **ครัวเรือน**

ครัวเรือนที่เปิดจากบ้านหรือบริษัทต้องใช้ Back กลับอาคารต้นทางนั้น บ้านพักปัจจุบันอาจเป็นอีกอาคารหนึ่ง Back/Esc ปิดรายละเอียดก่อน กลับจากครัวเรือนสู่อาคารต้นทาง แล้วจึงกลับแผนที่ เมื่อเปลี่ยนสถานที่ต้องไม่มีข้อมูลเก่าค้างแทนเจ้าของใหม่

ภาพรวมเมืองแยก **stock ตอนนี้** เช่น เงินคลังและสินค้าคงคลัง ออกจาก **flow ในช่วงวันที่ระบุ** ช่วงรวมวันต้นและวันปลาย ย้อนหลังไม่เกิน 30 วัน เงินเข้าออกนับเฉพาะรายการที่เกี่ยวข้องกับคลังเมือง หากทุนตั้งเมืองอยู่ในช่วงนั้นต้องรวมตามรายการจริง สินค้าส่งออกขายไม่นับการตัดสต็อกทิ้งจากรื้อถอนเป็นยอดขาย

## สถานะตรวจระหว่างเตรียม review

- Unit tests **21 ผ่าน**, production build และ asset verification **ผ่าน** ตามรอบ local ที่รายงานก่อนจัดหลักฐานนี้
- Normal และ blocked-model browser suites **ยังไม่เสร็จ**; จะเติมผลจริงและรายงานหลังรอบสุดท้าย ห้ามตีความว่า browser acceptance ผ่านแล้ว
- Independent review พบและทำซ้ำปัญหา **กดปุ่มค้างขณะเร่งเวลา 10×** ได้ การแก้ไข/ตรวจซ้ำยังเป็นงานค้างของรอบนี้ ต้องมีผล regression ก่อนปิดประเด็น
- CI ของ source commit สุดท้ายยังต้องตรวจหลัง push

รายการตรวจ browser ที่ต้องเก็บหลักฐาน: บ้าน A/B, บริษัท A/B, การเปิดครัวเรือนและ Back กลับต้นทาง, รายการเฉพาะ wallet, ช่วง 30 วันกับ stock ปัจจุบัน, ความช่วยเหลือแยกหน้า, เปลี่ยนสถานที่/โหลดเมืองแล้วไม่มีข้อมูลค้าง, ปุ่มค้างระหว่าง tick 10× และพฤติกรรมเมื่อ GLB โหลดไม่ได้

```sh
npm test
npm run assets:verify
npm run build
npm run preview
```

เมื่อ production preview ทำงาน ให้รัน suites ทีละตัวในอีก terminal:

```sh
npm run test:browser
npm run test:submenus
npm run test:context
```

ตรวจซ้ำโดยตั้ง `CITYMANAGER_BLOCK_MODELS=1` เพื่อครอบคลุม procedural fallback การตรวจมือถือใช้ viewport/touch จำลองใน Edge รวมกรณี layout กว้างบนหน้าจอแคบ **ไม่ใช่การทดสอบโทรศัพท์จริงหรือยืนยัน desktop mode ของ browser ผู้ใช้**

งานนี้เปลี่ยน GUI และการอ่านข้อมูลเท่านั้น ไม่เปลี่ยนสูตรเศรษฐกิจ tick, RNG, save schema, asset หรือ dependency งานฟาร์ม เหมือง วัตถุดิบ และสูตรการผลิตเป็นแผนเศรษฐกิจระยะถัดไปที่บันทึกไว้ในเอกสารออกแบบ ยังไม่ใช่ระบบที่นำมาใช้หรือค่าที่แสดงว่าจำลองแล้วใน preview นี้
