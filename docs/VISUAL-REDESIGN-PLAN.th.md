# แผนปรับปรุงความสวยงามทั้งหมด (Visual Redesign)

สถานะ: **ร่างแผน รอยืนยันก่อนลงมือ** · อ้างอิงโค้ดที่ `main` @ `72e61e9` (รุ่น 0.4.3)

ภาพก่อนปรับ: [desktop](visual-redesign-preview/before-desktop.png) · [desktop + ภาพรวมเมือง](visual-redesign-preview/before-desktop-city.png) · [มือถือ](visual-redesign-preview/before-mobile.png) · [มือถือ + ภาพรวมเมือง](visual-redesign-preview/before-mobile-city.png)

แผนนี้ปรับเฉพาะ **ภาพและการจัดวาง** ไม่แตะกติกาจำลอง เศรษฐกิจ หรือรูปแบบเซฟ ข้อความภาษาไทยและความหมายของแต่ละปุ่มยังเหมือนเดิม

---

## 1. ปัญหาที่เห็นตอนนี้

### ฉาก 3D
- พื้นเป็นสีเขียวเรียบผืนใหญ่ แสงแบน ไม่มีเงา (`castShadows: false`) อาคารดูลอยและไม่มีมิติ
- ฉากหลังเป็นสีฟ้าอมเทาทึบ (`clearColor`) ขอบแผนที่ดูเป็นกล่องวางบนโต๊ะ ไม่เหมือนเมือง
- โซน R/C/I/F เป็นสี่เหลี่ยมสีสดเต็มช่อง ตัดกับพื้นแรงเกินไปและแย่งความสนใจจากอาคาร
- ต้นไม้ขอบแผนที่ใหญ่เกินสเกลแปลง ประตูทางเข้าสีทองดูเป็นแท่งสี่เหลี่ยม
- สีในฉากกำหนดตรงในโค้ดกระจายใน `renderer.ts` / `terrain.ts` ไม่มีชุดสีกลาง

### GUI
- ตัวอักษรเล็กมาก (10–13px) โดยเฉพาะ dock เครื่องมือ ป้ายสถานะ และข้อความช่วย อ่านยากบนจอใหญ่
- ฟอนต์ `Segoe UI/Tahoma` ไม่มีบน Linux/Android ทำให้ภาษาไทยเปลี่ยนหน้าตาไปตามเครื่อง
- มุมซ้ายบนแน่น: wordmark + เวลา + แป้นกล้อง 9 ปุ่มซ้อนกัน แป้นกล้องกินพื้นที่ทั้งที่มีเมาส์/ท่าทางอยู่แล้ว
- แผงภาพรวมเมืองเป็นตารางการ์ดน้ำหนักเท่ากันหลายสิบใบ (ค่าส่วนใหญ่เป็น 0) ไม่มีลำดับความสำคัญ ตัวเลขหลักอย่างเงินคลังกับประชากรจมอยู่ในกลุ่ม
- สีเน้น amber `#f3c46b` ใช้ทั้งสถานะ active ปุ่ม เงิน และคำเตือน จนแยกความหมายไม่ได้

### โค้ด CSS
- 11 ไฟล์ เขียนแบบบรรทัดเดียว (minified ด้วยมือ) แก้ยากและ diff อ่านไม่ออก
- ไฟล์รุ่นหลัง (`compact-layout.css`, `submenu-layout.css`, `context-layout.css`) ทับกฎไฟล์ก่อนหน้า มี `!important` และสีฮาร์ดโค้ดซ้ำ (amber ซ้ำ 37 ครั้ง)
- มีตัวแปรเพียงไม่กี่ตัวใน `:root` ไม่มี scale ของระยะ ขนาดตัวอักษร รัศมีมุม หรือเงา

## 2. ทิศทางการออกแบบ

**"แผนที่เมืองยามบ่าย"** — โทนอบอุ่น สะอาด อ่านง่าย แบบเกมสร้างเมืองสมัยใหม่ ให้ฉาก 3D เป็นพระเอก ส่วน GUI เป็นกระจกขุ่นบางๆ ที่ถอยออกมาเมื่อไม่ได้ใช้

- **ฉาก:** แสงอาทิตย์เฉียงพร้อมเงานุ่ม ท้องฟ้าไล่สีแทนสีทึบ พื้นมีลวดลายหญ้า/ดินเล็กน้อย น้ำรอบเกาะแทนกล่องพื้น
- **GUI:** แผงสีเข้มโปร่งแสงพร้อม blur ขอบบาง มุมโค้งสม่ำเสมอ ตัวอักษรใหญ่ขึ้นหนึ่งขั้น ตัวเลขใช้ tabular figures
- **สีมีความหมายเดียว:** สีเน้นหลักสำหรับ "เลือก/active" สีเงินสำหรับ "เงิน" สีเขียว/แดงสำหรับ "ดี/มีปัญหา" และสีโซน R/C/I/F ที่ใช้ชุดเดียวกันทั้งใน GUI และในฉาก
- **รองรับโหมดสว่างไม่อยู่ในขอบเขตรอบนี้** — เกมใช้ธีมมืดชุดเดียว เพื่อไม่ให้งานบานปลาย

## 3. ขั้นตอนดำเนินงาน

แบ่งเป็น 5 เฟส แต่ละเฟสเป็น PR แยก ตรวจและ merge ได้ทีละชิ้น ไม่ทำให้เกมพังกลางทาง

### เฟส 0 — รื้อโครง CSS (ไม่เปลี่ยนหน้าตา)
1. จัดรูปแบบ CSS ทั้ง 11 ไฟล์ให้อ่านได้ (หนึ่งกฎต่อบรรทัด) ตรวจด้วย screenshot ว่าหน้าตาเหมือนเดิมทุกพิกเซลที่ทำได้
2. สร้าง `src/styles/tokens.css` รวม design tokens: สี (พื้นผิว ข้อความ เส้น สีเน้น สีสถานะ สีโซน) ระยะ (4/8/12/16/24/32) ขนาดตัวอักษร รัศมีมุม เงา ความเร็ว animation
3. แทนสีฮาร์ดโค้ดทั้งหมดด้วย token และรวมไฟล์ override (`compact-layout`, `submenu-layout`, `context-layout`) เข้ากับไฟล์ต้นทางของคอมโพเนนต์นั้น ลบ `!important` ที่ไม่จำเป็น
4. จัดโฟลเดอร์ `src/styles/` ตามคอมโพเนนต์: `base`, `hud`, `dock`, `inspector`, `cards`, `panels`

ผลลัพธ์: หน้าตาเดิม แต่การเปลี่ยนธีมในเฟสถัดไปแก้ที่ token จุดเดียว

### เฟส 1 — ตัวอักษร สี และองค์ประกอบพื้นฐาน
1. ใช้ฟอนต์ไทยที่ฝังมากับเกม (เช่น **IBM Plex Sans Thai** หรือ **Noto Sans Thai** แบบ self-host ใน `public/` ไม่โหลดจากภายนอก) พร้อม tabular numbers สำหรับเงิน/จำนวน
2. ขยาย type scale ขั้นต่ำ 12px บนมือถือ ข้อความหลัก 14px ตัวเลขสำคัญ 20–28px
3. กำหนดชุดสีใหม่ตามข้อ 2 และตรวจ contrast WCAG AA (4.5:1 สำหรับข้อความ)
4. ปรับปุ่ม ชิป แท็บ details/summary และ focus ring ให้เป็นชุดเดียวกัน (สถานะ hover / pressed / active / disabled ครบ)
5. เปลี่ยนไอคอนตัวอักษร Unicode (↖ ╋ ⌫ ✥ ▤ ☰) เป็นไอคอน SVG ชุดเดียวกัน (inline SVG sprite ไม่เพิ่ม dependency)

### เฟส 2 — จัดวาง HUD ใหม่
1. **แถบบน:** wordmark เล็กลงด้านซ้าย ตามด้วยตัวเลขหลักของเมืองแบบสรุป (เงินคลัง · ประชากร · งานว่าง) ให้เห็นตลอดโดยไม่ต้องเปิดแผง ปุ่มเมือง/คู่มือ/เกมอยู่ขวา
2. **เวลา:** ย้ายรวมกับแถบบน แสดง วัน/เดือน และปุ่มความเร็วเป็นกลุ่มเดียว
3. **กล้อง:** ซ่อนแป้น 9 ปุ่มบน desktop เหลือปุ่มหมุน/รีเซ็ต/ซูมแบบแนวตั้งเล็กๆ มุมขวาล่าง บนมือถือคงปุ่มเปิดแป้นไว้ตามเดิม
4. **Dock เครื่องมือ:** ปุ่มใหญ่ขึ้น ไอคอน + ชื่อ + ปุ่มลัด แยกกลุ่ม "สร้าง" (ถนน R C I F) กับ "เครื่องมือ" (เลือก รื้อ เลื่อน) ให้สีโซนบนปุ่มตรงกับสีในฉาก
5. **สถานะ/คำแนะนำ:** รวมเป็น toast ใบเดียวเหนือ dock จางหายเองเมื่อไม่มีอะไรใหม่
6. คง id และ `aria-*` เดิมทั้งหมด เพื่อให้ `main.ts` และ browser tests ใช้ต่อได้

### เฟส 3 — แผงข้อมูล (Inspector) และการ์ด
1. **ภาพรวมเมือง:** เปิดด้วยแถว KPI ใหญ่ 3–4 ตัว (เงินคลัง ประชากร การจ้างงาน ความต้องการ R/C/I) ตามด้วยกลุ่มรายละเอียดที่พับได้ ค่าที่เป็น 0 ทั้งกลุ่มแสดงเป็นข้อความสั้นแทนการ์ดเปล่าหลายใบ
2. **แถบความต้องการ (demand):** แสดงเป็นแท่งสีตามโซน แทนตัวเลขล้วน
3. **การ์ดอาคาร:** ส่วนหัวมีภาพ/ไอคอนประเภท สีโซน และสถานะ (ทำงาน / ขาดแรงงาน / ขาดวัตถุดิบ) เป็น badge ชัดเจน
4. **บัญชีเงิน/สินค้า:** ตารางมีเส้นแบ่งบางๆ ตัวเลขชิดขวา รายรับเขียว รายจ่ายแดง
5. **มือถือ:** แผงเป็น bottom sheet ที่ลากขึ้นลงได้ 3 ระดับ (peek / ครึ่งจอ / เต็มจอ) แทนการเต็มจอทันที
6. เพิ่ม transition เปิด/ปิดแผงสั้นๆ (≤200ms) และเคารพ `prefers-reduced-motion`

### เฟส 4 — ฉาก 3D
1. ย้ายสีทั้งหมดใน `renderer.ts`, `terrain.ts` ไปไว้ใน `src/scene-palette.ts` ใช้ค่าสีโซนชุดเดียวกับ tokens ใน CSS
2. **แสง:** เปิดเงาจากดวงอาทิตย์ (shadow map ขนาดพอดี ปรับตามคุณภาพอุปกรณ์) ปรับมุมแสงให้เฉียง ปรับ ambient ให้อุ่นขึ้น เพิ่ม tone mapping (ACES) และ gamma ที่ถูกต้อง
3. **ท้องฟ้าและขอบโลก:** ฉากหลังไล่สี + fog บางๆ ให้ขอบแผนที่กลืนไปกับระยะไกล เปลี่ยนกล่องพื้นรอบนอกเป็นผิวน้ำเรียบ
4. **พื้นดิน:** texture หญ้า/ดินแบบ procedural ความถี่ต่ำ เส้นกริดจางลงและแสดงชัดเฉพาะตอนใช้เครื่องมือวาง
5. **โซน:** เปลี่ยนจากสี่เหลี่ยมทึบเป็นพื้นโปร่งแสง + ขอบสีโซน เมื่ออาคารเกิดแล้ว พื้นโซนจางลงอีก
6. **รายละเอียด:** ลดสเกลต้นไม้ให้สมจริง กระจายต้นไม้เล็กแบบสุ่มคงที่ (seeded) ปรับประตูทางเข้าให้เป็นซุ้มที่มีรูปทรง เพิ่มเส้นขอบทางเท้า
7. **Feedback การวาง:** ไฮไลต์ช่องที่ hover ช่องที่วางได้/ไม่ได้ (เขียว/แดง) และ preview ถนนก่อนยืนยัน
8. คง procedural fallback เมื่อโหลดโมเดล Kenney ไม่ได้ และกำหนดงบประสิทธิภาพ: ≥ 50 fps บน desktop ทั่วไป, ≥ 30 fps บนมือถือระดับกลาง ถ้าไม่ถึงให้ปิดเงาอัตโนมัติ

### เฟส 5 — เก็บงานและเอกสาร
1. ถ่ายภาพ "หลังปรับ" ชุดเดียวกับภาพก่อนปรับ (desktop / มือถือ / แผงเปิด) ไว้ใน `docs/visual-redesign-preview/`
2. อัปเดต `README.md`, `docs/GUI-ASSETS.md` (ฟอนต์ + ไอคอนใหม่ พร้อม license) และเขียน `docs/DESIGN-TOKENS.md` อธิบาย token
3. อัปเดตตัวเลขขนาดฟอนต์/ระยะที่ browser tests ตรวจอยู่ (เช่น `compact-smoke`, `building-cards-smoke`) ให้ตรงกับดีไซน์ใหม่ โดยยังตรวจเงื่อนไขขั้นต่ำเดิม (ขนาดตัวอักษร ปุ่มแตะ ≥ 44px ไม่ทับกัน)

## 4. ข้อจำกัดที่ต้องรักษา

- ไม่เปลี่ยน `sim.ts`, กติกาเศรษฐกิจ หรือรูปแบบเซฟ v1–v6
- คง id, `data-*` และ `aria-*` ที่ `main.ts` และ tests อ้างถึง เปลี่ยนได้เฉพาะ class/โครงที่ไม่มีใครอ้าง
- ปุ่มแตะทุกปุ่ม ≥ 44×44px, focus มองเห็นได้, ใช้คีย์บอร์ดได้ครบเหมือนเดิม
- ไม่โหลดทรัพยากรจากภายนอกตอนเล่น (ฟอนต์/ไอคอน self-host) และ asset ใหม่ต้องเป็น CC0/OFL พร้อมบันทึก license
- `npm test`, `npm run build`, `assets:verify` และ browser suites ต้องผ่านทุกเฟส

## 5. ความเสี่ยง

| ความเสี่ยง | การรับมือ |
|---|---|
| Browser tests ตรวจขนาดฟอนต์/ตำแหน่ง จะล้มเมื่อเปลี่ยนดีไซน์ | ปรับค่าคาดหวังใน PR เดียวกับดีไซน์ และอธิบายเหตุผลใน PR |
| เงาและ post-processing ทำให้มือถือช้า | ระดับคุณภาพอัตโนมัติ + ปิดเงาเมื่อ fps ต่ำ |
| ฟอนต์ไทยเพิ่มขนาดดาวน์โหลด | ใช้ subset เฉพาะน้ำหนักที่ใช้ (2 น้ำหนัก) รูปแบบ woff2 |
| งานใหญ่ ทำให้ PR ค้างนาน | แยก 5 PR ตามเฟส เฟส 0 ไม่เปลี่ยนหน้าตาจึง merge ได้เร็ว |

## 6. คำถามที่อยากให้ตัดสินใจก่อนเริ่ม

1. ชอบทิศทาง **"แผนที่เมืองยามบ่าย"** (ธีมมืดอบอุ่น ฉากสว่าง) หรืออยากได้แนวอื่น เช่น สว่างทั้งหมด / มินิมอลแบบแผนที่ / การ์ตูนสีสด
2. ฟอนต์: **IBM Plex Sans Thai** (ทันสมัย เป็นทางการ) หรือ **Noto Sans Thai** (กลาง อ่านง่าย) หรือมีฟอนต์ในใจ
3. ทำทีละเฟสเป็น PR แยก (แนะนำ) หรือรวมเป็น PR เดียว
4. เริ่มจากฝั่งไหนก่อน — **GUI (เฟส 0–3)** หรือ **ฉาก 3D (เฟส 4)** ทั้งสองฝั่งแยกกันได้
