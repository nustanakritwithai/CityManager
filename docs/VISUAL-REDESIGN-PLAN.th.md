สถานะ: **ร่างแผน รอยืนยันก่อนลงมือ** · อ้างอิงโค้ดที่ `main` @ `72e61e9` (รุ่น 0.4.3, เซฟ `6 / growth-1`)

ภาพก่อนปรับ: [desktop](visual-redesign-preview/before-desktop.png) · [desktop + ภาพรวมเมือง](visual-redesign-preview/before-desktop-city.png) · [มือถือ](visual-redesign-preview/before-mobile.png) · [มือถือ + ภาพรวมเมือง](visual-redesign-preview/before-mobile-city.png)

แผนนี้ปรับเฉพาะ **ภาพ การจัดวาง และการแสดงข้อมูลที่ระบบมีอยู่แล้ว** ไม่แตะกติกาจำลอง เศรษฐกิจ หรือรูปแบบเซฟ ฟังก์ชันใหม่ที่เพิ่มต้องเป็นการอ่านข้อมูลอย่างเดียว (read-only projection) เหมือน `context-data.ts` และ `building-card-data.ts` ในปัจจุบัน

## 1. สำรวจระบบในเกม: มีข้อมูลอะไร แสดงที่ไหน ขาดอะไร

สำรวจจาก `sim.ts`, `agriculture*.ts`, `labor.ts`, `housing.ts`, `context-data.ts`, `context-panels.ts`, `building-card-data.ts`, `inspector-data.ts`, `submenus.ts`, `signal-*`, `city-questions*`, `entity-explanation-*`, `renderer.ts`, `terrain.ts` และ `main.ts`

### 1.1 เวลาและรอบการคำนวณ
| ข้อมูลในระบบ | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| 1 tick = 1 วัน, 30 วัน = 1 เดือน, ความเร็ว Pause/1×/3×/10× | `วันที่ N · เดือน M` + ปุ่มความเร็ว | ไม่รู้ว่าอีกกี่วันจะถึงวันชำระรายเดือน (ค่าจ้าง ค่าเช่า ภาษี) |
| ทบทวนการเติบโตทุก 3 วัน (`tick % 3`) อัปเกรดความสูงทุกสิ้นเดือน | แสดงเฉพาะในเหตุผลของแปลงว่าง ("ทบทวนอีก N วัน") | ไม่มีตัวนับรอบทบทวนที่เห็นตลอด |
| สถานะหยุดเวลา | ไอคอน Ⅱ/▶ เล็ก | ไม่มีสัญญาณชัดว่าเกมหยุดอยู่ (เช่น กรอบจอ/ป้าย "หยุด") |

### 1.2 ถนน ประตูเมือง และการเชื่อมต่อ
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| ประตูภายนอกฝั่งตะวันตก (ช่อง 288) และถนนที่เชื่อมด้วย BFS | ถนนที่ไม่เชื่อมเป็นสีแดงอิฐ, ป้าย "ถนนเชื่อมถึงเมือง/ขาดการเชื่อมต่อ" ในแผง | แปลง/อาคารที่ขาดการเชื่อมต่อไม่มีสัญลักษณ์บนแผนที่ |
| ค่าสร้าง 50 เครดิต/ช่อง, บำรุง 0.10/ช่อง/วัน, รื้อ 20 | ค่าสร้างแสดงหลังเลือกถนนแล้วเท่านั้น | ไม่มีราคาและจำนวนช่องระหว่างลากถนน หรือก่อนกดรื้อ |
| ผลลัพธ์การสร้าง/โซน/รื้อ (`Result.message`) | ชิปสถานะ | **ข้อความเป็นภาษาอังกฤษ** ("Built 3 road cells.") ปนกับ UI ภาษาไทย |

### 1.3 โซน R/C/I/F และความอุดมสมบูรณ์ของดิน
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| โซน 4 ประเภท, ฟาร์มต้อง fertility ≥ 50% ต่อแปลง (ค่า 0–100 จาก seed) | สี่เหลี่ยมสีเต็มช่อง, ค่า fertility แสดงในข้อความช่วยเมื่อ hover ด้วยเครื่องมือ F | **ไม่มีแผนที่ความอุดมสมบูรณ์** ผู้เล่นต้อง hover ทีละช่อง |
| เงื่อนไขที่ขวางการเติบโตต่อแปลง (`blockers`) | รายการเหตุผลในแผงเมื่อแตะแปลง | บนแผนที่ไม่รู้ว่าแปลงไหน "พร้อมเกิด" หรือ "ติดเงื่อนไข" |
| ขีดจำกัดต้นแบบ: อาคาร 192, กิจการ 64, ครัวเรือน 128 | ข้อความเหตุผลเมื่อเต็ม | ไม่มีตัวบอกว่าใกล้เต็ม |

### 1.4 ความต้องการ (Demand) และการเติบโต
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| `summary.demand` R/C/I/F (ตัวเลข) | กริดตัวเลขในหน้าภาพรวมเมือง | ไม่เห็นตลอดเวลา ต้องเปิดแผง ไม่มีภาพแท่งแบบเกมสร้างเมือง |
| การเกิดอาคาร (`createBuilding`), อัปเกรดระดับรายเดือน (R≤3, C≤4, I≤3) | อาคารปรากฏ/สูงขึ้นเงียบๆ | ไม่มีแอนิเมชันก่อสร้าง ไม่มีแจ้งเตือน |
| สถานะขยายโรงงาน `industryGrowthStatus` 9 รหัส + ทุนสำรอง (ค่าจ้าง ภาษี ค่าเช่า เงินหมุนเวียน) เทียบทุน 3,000 เครดิต | การ์ดตัวเลขหลายใบ + ข้อความ | ควรเป็น **แถบความคืบหน้าทุน** และ **เช็กลิสต์เงื่อนไข** ทีละข้อ |

### 1.5 ครัวเรือน การย้ายเข้า และที่พัก
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| ครัวเรือน: สมาชิก กำลังแรงงาน ผู้พึ่งพิง โปรไฟล์ (เดี่ยว/ครอบครัว/legacy) เงินร่วม `needs` ซื้อล่าสุด | การ์ดครัวเรือนครบ | ภาพการ์ดเป็นตัวเลขล้วน ไม่มีภาพแทนสมาชิก |
| บ้าน cottage ระดับ 1–3 = 1/2/3 ครัวเรือน, 4/8/12 คน | "พักอยู่ / รับได้" เป็นตัวเลข | ควรเป็นแถบหรือจุดแสดงการเข้าพัก |
| ย้ายเข้าไม่เกินวันละ 1 ครัวเรือน, สิทธิเริ่มเมือง 2 ครัวเรือน, ครัวเรือนรอที่พัก | เหตุผลในการ์ดบ้าน, คำเตือนในภาพรวม | **ไม่แจ้งเมื่อมีครัวเรือนย้ายเข้า** (`lastEvent` ไม่ถูกแสดงเลย) |

### 1.6 แรงงานและการจ้างงาน
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| ทักษะ 3 กลุ่ม (ทั่วไป/การผลิต/ค้าปลีก), การจัดสรรงานต่อกิจการ, แรงงานเจ้าของตลาด | รายการในการ์ดครัวเรือนและกิจการ | ควรใช้ชิปสีตามทักษะ และแถบ "ทำงาน / ว่าง" |
| ค่าจ้าง I 600, C 420, F 420 เครดิต/เดือน สะสมเป็นวันทำงาน, ภาษีค่าจ้าง 10% | "สำรองค่าจ้าง" ในการ์ด | ไม่มีภาพรวมตลาดแรงงานทั้งเมือง (งานว่างตามประเภท vs แรงงานว่างตามทักษะ) |

### 1.7 กิจการ: ร้านค้า ตลาด โรงงาน ฟาร์ม
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| ประเภท: ร้านค้าสำเร็จรูป (เดิม ระดับ 2–4), ตลาด C ระดับ 1, โรงงาน, ฟาร์ม; ความจุงาน; กำไรเดือนก่อน; ค่าเช่า 30/100; ภาษีกำไร 20%; `fundedBy` | การ์ดตามประเภท (PR #13) | ข้อมูลครบแต่น้ำหนักเท่ากันหมด ไม่มี "สถานะเดียวที่สำคัญที่สุด" ด้านบน |
| **สถานะการทำงานรายกิจการ** `economicSignals()` → `agriculture.no-road / no-utilities / no-workers / unsuitable-fertility / stock-cap / harvest-ready / no-input / recipe-ready / no-buyer / no-stock / market-ready` | **คำนวณแล้วแต่ไม่ได้แสดงที่ใดใน GUI** (ใช้เฉพาะ QA) | ควรเป็น **ป้ายสถานะบนการ์ด** และ **ไอคอนลอยเหนืออาคารในฉาก 3D** |
| การเงินเจ้าของตลาด: เติมทุน/ถอนกำไรครั้งละ 100 พร้อมเหตุผลเมื่อทำไม่ได้ | ปุ่มสองปุ่ม + ข้อความ | ปุ่มควรแสดงยอดที่ทำได้และเหตุผลที่ถูกปิดชัดเจน |

### 1.8 ห่วงโซ่เกษตรและสินค้า
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| ฟาร์มเก็บเกี่ยว `floor(24 × fertility%) × แรงงาน` เก็บได้ 96 ล็อต; ตลาดเก็บ 48; โรงงาน 24 | ตัวเลขในการ์ด | — |
| ราคา: ฟาร์ม→ตลาด 1.50, ตลาด→โรงงาน 3.00, ฟาร์ม→โรงงาน 3.50, ตะกร้าครัวเรือน 8.00 | ตัวเลขในการ์ดตลาด | — |
| สูตรโรงงาน 2 ล็อต → 8 สินค้า; ขายส่ง 3.00, นำเข้า 4.50, ส่งออก 3.50 | การ์ดโรงงานแบบ input → recipe → output | — |
| ยอด 30 วัน: เก็บเกี่ยว/แปรรูป/บริโภค/ตัดทิ้ง, ผลิต/นำเข้า/บริโภค/ส่งออก | การ์ดตัวเลข 8+ ใบในภาพรวม | **ไม่มีแผนภาพห่วงโซ่ทั้งเมือง** ฟาร์ม → ตลาด → โรงงาน → ร้านค้า → ครัวเรือน / ภายนอก |

### 1.9 เงินและบัญชี
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| บัญชี: คลังเมือง, ครัวเรือน, กิจการ, ภายนอก, ก่อสร้าง, ถนน, บำรุง, ผู้ให้เช่า; ทุกการโอนมีคู่บัญชี | รายการเงินล่าสุด, ยอดกระเป๋าเงิน (submenu) | รายการยาว อ่านยาก ไม่มีสีรับ/จ่าย |
| คลังเมือง, รายรับ/รายจ่าย/สุทธิ 30 วัน | การ์ดในภาพรวม | **ไม่เห็นเงินคลังตลอดเวลา**, ไม่มีกราฟแนวโน้ม (คำนวณย้อนจาก ledger ได้แบบอ่านอย่างเดียว), ไม่มีแยกรายจ่ายตามประเภท |
| หน่วยเงิน | UI ใช้ "฿/บาท" ส่วนข้อความระบบใช้ "เครดิต" | **หน่วยไม่สม่ำเสมอ** ต้องเลือกหน่วยเดียว |

### 1.10 สาธารณูปโภคและคำเตือน
| ข้อมูล | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| น้ำ/ไฟจากภายนอก (`utilities.power/water`) | คำเตือนเมื่อไม่พร้อม | ไม่มีไอคอนสถานะใน HUD |
| `cityOverview.warnings` (แรงงานว่าง, ไร้บ้าน, ยังไม่ได้ซื้อของ, อาคารขาดถนน, คลังหมด) | ข้อความในหน้าภาพรวม | ควรมี **ศูนย์แจ้งเตือน** พร้อมจำนวนบนปุ่มใน HUD และแตะแล้วพาไปยังจุดนั้น |
| `lastEvent` (อาคารเกิด, ครัวเรือนย้ายเข้า, ชำระรายเดือน, ID หมด) | **ไม่ได้แสดง** | ควรเป็น **บันทึกเหตุการณ์ (event feed)** ฝั่ง UI ไม่บันทึกลงเซฟ |

### 1.11 เซฟ/โหลด

### 1.12 ระบบทดลอง (Typhoon / ข้อมูลอ่านอย่างเดียว)
| ระบบ | แสดงตอนนี้ | ช่องว่าง |
|---|---|---|
| สัญญาณเมือง (`?signals=1`): จับภาพ 9 ค่า, เทียบภาพก่อนหน้า, สถานะ รอ/ยกเลิก/ออฟไลน์/ล้าสมัย | หน้าแยกในแผง | สถานะหลายแบบใช้หน้าตาเดียวกัน |
| คำถามข้อเท็จจริง 5 แบบ (เมือง/ที่พัก/แรงงาน/บ้าน/กิจการ) | disclosure ในหน้าสัญญาณ | — |
| คำอธิบายรายการที่เลือก (entity explanation) | ส่วนท้ายการ์ดอาคาร | ต้องแยกให้ชัดว่า "ข้อเท็จจริง" vs "ข้อสันนิษฐาน" vs "ควรตรวจต่อ" |

ทั้งสามระบบควรใช้ **ภาษาภาพเดียวกัน**: ป้าย "ทดลอง", สถานะ loading/stale/error/offline ที่แยกสีและไอคอน และกล่องอ้างอิงที่พับได้

### 1.14 ฉาก 3D และ asset
- โมเดล Kenney CC0: บ้าน 2 แบบ ร้าน 2 แบบ โรงงาน 2 แบบ ต้นไม้ ไฟถนน + procedural fallback

- แสง: ทิศทางเดียว ไม่มีเงา, ambient เทาฟ้า, clear color ทึบ

## 2. สรุปสิ่งที่ต้องเพิ่มเพื่อให้การแสดงผลครบ

เรียงตามผลต่อการเล่น:

1. **แถบสรุปเมืองบน HUD** เงินคลัง (+ สุทธิ 30 วัน), ประชากร/ครัวเรือน, งาน/แรงงานว่าง, ไอคอนน้ำ-ไฟ
2. **แถบ Demand R/C/I/F** ข้าง dock เครื่องมือ สีเดียวกับโซน
3. **บันทึกเหตุการณ์ + toast** จาก `lastEvent` และผลการกระทำ แปลเป็นภาษาไทยในชั้น UI (แบบเดียวกับ `shortReason`)
4. **ศูนย์แจ้งเตือน** จาก `cityOverview.warnings` พร้อมตัวเลขบนปุ่ม
5. **ป้ายสถานะกิจการ** จาก `economicSignals()` ทั้งบนการ์ดและเหนืออาคารในฉาก
6. **Overlay แผนที่** (เปิดจากปุ่มเดียว): ความอุดมสมบูรณ์, การเชื่อมถนน, แปลงพร้อมเกิด/ติดเงื่อนไข, การเข้าพักบ้าน
7. **แผนภาพห่วงโซ่สินค้า** ในภาพรวมเมือง พร้อมยอด 30 วัน
8. **กราฟเงินคลัง 30 วัน** และรายจ่ายแยกประเภท (คำนวณย้อนจาก ledger อ่านอย่างเดียว)
9. **ราคาระหว่างลากถนน/ก่อนรื้อ** และกรอบเขียว/แดงว่าวางได้หรือไม่ได้
10. **ตัวนับรอบ** วันชำระรายเดือน และรอบทบทวนการเติบโต 3 วัน
11. **เช็กลิสต์การขยายโรงงาน** + แถบทุนสะสม
12. **หน้าเซฟจัดกลุ่มใหม่** + ปุ่มเริ่มใหม่แบบยืนยัน
13. **หน่วยเงินเดียว** ทั้งเกม (ข้อเสนอ: "เครดิต" ตามระบบ พร้อมสัญลักษณ์ ¢ หรือไอคอนเหรียญ — รอผู้เล่นเลือก)

## 3. ทิศทางการออกแบบ

**"แผนที่เมืองยามบ่าย"** โทนอบอุ่น สะอาด อ่านง่าย ให้ฉาก 3D เป็นพระเอก GUI เป็นแผงกระจกขุ่นบางๆ ที่ถอยออกเมื่อไม่ได้ใช้

- **สีมีความหมายเดียว:** เน้นหลัก = เลือก/active, ทอง = เงิน, เขียว/เหลือง/แดง = ปกติ/ต้องดู/มีปัญหา, สีโซน R/C/I/F ใช้ชุดเดียวกันทั้ง GUI และฉาก
- **สถานะทุกระบบใช้ชุดเดียว:** ป้ายสถานะ 3 ระดับ + ไอคอน ใช้ซ้ำในการ์ด แจ้งเตือน overlay และไอคอนลอยในฉาก
- **ลำดับข้อมูลในการ์ดทุกประเภท:** (1) ชื่อ + สถานะหลัก (2) KPI 3–4 ตัว (3) ความคืบหน้า/ความจุเป็นแถบ (4) รายละเอียดพับได้ (5) บัญชีและหลักฐาน
- ธีมมืดชุดเดียว ไม่ทำโหมดสว่างรอบนี้

## 4. ขั้นตอนดำเนินงาน

แบ่งเป็น 7 เฟส แต่ละเฟสเป็น PR แยก เฟส 0 ไม่เปลี่ยนหน้าตา

### เฟส 0: รื้อโครง CSS (หน้าตาเหมือนเดิม)
1. จัดรูปแบบ CSS 11 ไฟล์ให้อ่านได้ ตรวจด้วย screenshot ว่าหน้าตาเหมือนเดิม
2. สร้าง `src/styles/tokens.css`: สีพื้นผิว/ข้อความ/เส้น/เน้น/สถานะ/โซน, ระยะ 4–32, ขนาดตัวอักษร, รัศมี, เงา, ความเร็ว animation
3. แทนสีฮาร์ดโค้ด (amber ซ้ำ 37 ครั้ง) ด้วย token และรวมไฟล์ override (`compact-layout`, `submenu-layout`, `context-layout`) เข้ากับไฟล์ต้นทาง ลบ `!important` ที่ไม่จำเป็น
4. ย้ายสีโซนที่ซ้ำอยู่ใน `main.ts` (`symbol()`), `renderer.ts`, `terrain.ts` ไปที่ `src/palette.ts` ไฟล์เดียว ใช้ร่วมกันทั้ง GUI และฉาก

### เฟส 1: ตัวอักษร สี และคอมโพเนนต์พื้นฐาน
1. ฟอนต์ไทยฝังมากับเกม (IBM Plex Sans Thai หรือ Noto Sans Thai, woff2 subset 2 น้ำหนัก, OFL) + tabular numbers
2. Type scale: ขั้นต่ำ 12px บนมือถือ, เนื้อหา 14px, ตัวเลข KPI 20–28px
3. คอมโพเนนต์กลางชุดเดียว: ปุ่ม, ชิป, **ป้ายสถานะ 3 ระดับ**, **แถบความคืบหน้า/ความจุ**, KPI tile, แถวบัญชี (รับเขียว/จ่ายแดง ชิดขวา), กล่องพับได้, toast
4. ไอคอน SVG ชุดเดียว (inline sprite) แทน Unicode ↖ ╋ ⌫ ✥ ▤ ☰ และไอคอนสถานะกิจการ 11 แบบ
5. ตรวจ contrast WCAG AA
6. เลือกหน่วยเงินเดียวและใช้ `formatMoney` ทุกจุด

### เฟส 2: HUD และข้อมูลที่ต้องเห็นตลอด
1. **แถบบน:** wordmark เล็ก · เงินคลัง (+ สุทธิ 30 วัน) · ประชากร · งานว่าง/แรงงานว่าง · ไอคอนน้ำ-ไฟ · ปุ่มแจ้งเตือน (มีตัวเลข) · เมือง/คู่มือ/เกม
2. **เวลา:** วัน/เดือน + วงแหวนความคืบหน้าของเดือน + "ชำระรายเดือนอีก N วัน" + ป้าย "หยุดอยู่" เมื่อ pause
3. **Dock เครื่องมือ:** ปุ่มใหญ่ขึ้น แยก "สร้าง" (ถนน R C I F) กับ "เครื่องมือ" (เลือก รื้อ เลื่อน overlay) พร้อม **แถบ Demand** เล็กบนปุ่มโซนแต่ละปุ่ม
4. **กล้อง:** desktop เหลือปุ่มหมุน/รีเซ็ต/ซูมแนวตั้งมุมขวาล่าง มือถือคงปุ่มเปิดแป้นเดิม
5. **Toast + บันทึกเหตุการณ์:** ผลการกระทำและ `lastEvent` แสดงเป็น toast เหนือ dock แล้วเก็บย้อนหลังใน "เหตุการณ์ล่าสุด" (เก็บในหน่วยความจำเท่านั้น ไม่เข้าเซฟ) แปลข้อความอังกฤษจาก sim เป็นไทยในชั้น UI โดยจับคู่ prefix แบบ `shortReason`
6. **ศูนย์แจ้งเตือน:** แผงเล็กจากปุ่มบน แสดง `warnings` + กิจการที่สถานะเป็นปัญหา แตะแล้วเลื่อนกล้องไปและเปิดการ์ด
7. คง id และ `aria-*` เดิมทั้งหมด

### เฟส 3: แผงข้อมูล (Inspector) และการ์ด
1. **ภาพรวมเมือง** แบ่งแท็บ: *สรุป* (KPI ใหญ่ + Demand + แจ้งเตือน), *ประชากรและที่พัก*, *แรงงาน* (งานว่างตามประเภท vs แรงงานว่างตามทักษะ), *เศรษฐกิจ* (แผนภาพห่วงโซ่ + กราฟเงินคลัง), *บัญชี* (ledger, สินค้า, พืชผล, กระเป๋าเงิน) กลุ่มที่เป็น 0 ทั้งหมดย่อเป็นบรรทัดเดียว
2. **แผนภาพห่วงโซ่สินค้า:** ฟาร์ม → ตลาด → โรงงาน → ร้านค้า → ครัวเรือน และ ภายนอก (นำเข้า/ส่งออก) เส้นหนาตามปริมาณ 30 วัน ราคาต่อหน่วยบนเส้น
3. **กราฟเงินคลัง 30 วัน** (sparkline) + รายจ่ายแยก ถนน/บำรุง/ก่อสร้าง และรายรับแยก ภาษีค่าจ้าง/ภาษีกำไร (helper อ่านอย่างเดียวใหม่ใน `context-data.ts`)
4. **การ์ดทุกประเภทใช้ลำดับเดียวกัน** (ข้อ 3):
   - *บ้าน:* แถบเข้าพักครัวเรือน/คน, รายชื่อครัวเรือนเป็นการ์ดย่อ, เช็กลิสต์เงื่อนไขรับผู้ย้ายเข้า
   - *ครัวเรือน:* ไอคอนสมาชิก (ทำงาน/ว่าง/ผู้พึ่งพิง), ชิปทักษะ, ที่ทำงาน, เงินร่วม, ซื้อล่าสุด
   - *ตลาด/ร้านค้า/โรงงาน/ฟาร์ม:* ป้ายสถานะจาก `economicSignals()` ด้านบนสุด, แถบแรงงาน, แถบสต็อกเทียบเพดาน (96/48/24), ขั้นตอน input → สูตร → output, การเงินเจ้าของตลาดพร้อมยอดที่ทำได้
   - *แปลงว่าง:* เช็กลิสต์ blockers (ถนน ✓ น้ำไฟ ✓ demand ✗ …) + นับถอยหลังรอบทบทวน
   - *ถนน:* สถานะเชื่อมต่อ ค่าบำรุง
5. **การขยายโรงงาน:** แถบทุนสะสม `availableCapital / 3,000` + เช็กลิสต์ 7 เงื่อนไขตามรหัส `growth.*` (น้ำไฟ, แปลง I ว่าง, งานว่างเดิม, ที่พัก, พืชผล ≥ 8 ล็อต, ผู้ลงทุนที่มีกำไร, ทุนพอ)
6. **หน้าเกม:** จัดกลุ่มเซฟใหม่ แสดงวันในเกมของเซฟปัจจุบัน ปุ่มเริ่มใหม่ใช้ `<dialog>` ยืนยัน
7. **หน้าคู่มือ:** เพิ่มตารางปุ่มลัดและคำอธิบายสี/ไอคอนสถานะ
8. **ระบบทดลอง:** ใช้คอมโพเนนต์ป้ายสถานะและกล่องอ้างอิงชุดเดียวกัน แยก ข้อเท็จจริง / ข้อสันนิษฐาน / ควรตรวจต่อ ด้วยไอคอนและสี
9. **มือถือ:** แผงเป็น bottom sheet 3 ระดับ (peek / ครึ่งจอ / เต็มจอ), breadcrumb บนหัวแผง, transition ≤ 200ms เคารพ `prefers-reduced-motion`

### เฟส 4: ฉาก 3D: แสง พื้น และบรรยากาศ
1. เปิดเงาจากดวงอาทิตย์ (ระดับคุณภาพตามอุปกรณ์) มุมแสงเฉียง ambient อุ่น tone mapping ACES
2. ท้องฟ้าไล่สี + fog บางๆ เปลี่ยนกล่องพื้นรอบนอกเป็นผิวน้ำ
3. พื้นหญ้า/ดิน procedural ความถี่ต่ำ เส้นกริดจาง แสดงชัดเฉพาะตอนใช้เครื่องมือวาง
4. โซนเป็นพื้นโปร่งแสง + ขอบสีโซน จางลงเมื่ออาคารเกิด
5. ลดสเกลต้นไม้ กระจายต้นไม้แบบ seeded ประตูเมืองเป็นซุ้มมีรูปทรง ทางเท้าข้างถนน
6. งบประสิทธิภาพ ≥ 50 fps desktop, ≥ 30 fps มือถือระดับกลาง ต่ำกว่าให้ปิดเงาอัตโนมัติ คง procedural fallback

### เฟส 5: ฉาก 3D: ข้อมูลบนแผนที่
1. **Feedback การวาง:** กรอบเขียว/แดงตามผล `zoneCell`/`buildRoad` ล่วงหน้า (ตรวจแบบไม่เปลี่ยน state), ป้ายราคาและจำนวนช่องลอยตามเคอร์เซอร์ระหว่างลากถนนหรือก่อนรื้อ
2. **ไอคอนสถานะเหนืออาคาร** (billboard เล็ก) เฉพาะสถานะที่เป็นปัญหา: ขาดถนน, ขาดแรงงาน, ขาดวัตถุดิบ, สต็อกเต็ม, ไม่มีผู้ซื้อ, บ้านมีครัวเรือนรอ
3. **Overlay** สลับได้จากปุ่มใน dock (และเปิดเองเมื่อเลือกเครื่องมือ F):
   - ความอุดมสมบูรณ์ (heatmap, เส้นแบ่ง 50%)
   - การเชื่อมต่อถนน (เชื่อม/ไม่เชื่อม)
   - แปลงพร้อมเกิด / ติดเงื่อนไข
   - การเข้าพักบ้าน (ว่าง/เกือบเต็ม/เต็ม)
4. **แอนิเมชันก่อสร้าง/อัปเกรด** สั้นๆ (นั่งร้าน → อาคาร, เด้งเมื่อเพิ่มระดับ) ผูกกับเหตุการณ์ในบันทึก
5. อาคารที่ขาดการเชื่อมต่อแสดงเป็นสีจาง (desaturate)

### เฟส 6: เก็บงานและเอกสาร

- `npm test`, `npm run build`, `assets:verify` และ browser suites ต้องผ่านทุกเฟส
