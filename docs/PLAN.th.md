# แผน CityManager รุ่นทดลองแรก

เป้าหมายคือให้ผู้เล่นสร้างถนน กำหนดโซน ดูครัวเรือน/บริษัทตัดสินใจ และย้อนดูได้ว่าเงิน สินค้า และการเติบโตเกิดจากอะไร ใช้ PlayCanvas ตามคำขอล่าสุดและเขียนโค้ดใหม่ทั้งหมด

## ขอบเขตที่ส่ง review

| ส่วน | รุ่นทดลองแรก |
|---|---|
| โลก | แผนที่ราบ 24×24 ช่อง ถนนกริด ประตูตลาดภายนอกฝั่งตะวันตก |
| การเล่น | ถนน R/C/I เลือก ลบ หยุดเวลา/เร่งเวลา และบันทึกใน browser |
| ประชากร | ครัวเรือนมีเงิน งาน และความต้องการซื้อสินค้า |
| บริษัท | มีเงิน คนงาน inventory รายรับ/รายจ่าย และเงื่อนไขเติบโต |
| ความโปร่งใส | รายการโอนเงิน/สินค้าและเหตุผลเมื่ออาคารยังไม่เกิดหรือกิจกรรมหยุด |
| ภาพ | 3D รูปทรงเรียบง่าย ความสูงอาคารต่างกัน กล้อง pan/rotate/zoom |
| การตรวจ | headless simulation tests, production build และ browser smoke/visual checks |

## ลำดับงาน

1. ทำ simulation TypeScript ที่ไม่ผูกกับ renderer: seed, วัน, ถนน, parcel, ครัวเรือน, บริษัท และบัญชี
2. ตรวจการอนุรักษ์เงิน/สินค้า การเชื่อมต่อ เงื่อนไข bootstrap และการซื้อ/ค่าจ้างจริง
3. เชื่อมภาพ PlayCanvas และ DOM UI ที่มีปุ่มสัมผัสอย่างน้อย 44px พร้อม cancel/back ที่ชัดเจน
4. ตรวจการใช้เครื่องมือซ้ำ ถนนขาด ปุ่มกล้อง pause/speed และ save/load ต่อเนื่อง
5. สร้าง bundle ที่ใช้ `/CityManager/` เปิด draft PR พร้อมผลตรวจและภาพ แล้วรอ review ก่อน merge/เผยแพร่

## รับข้อกำหนดเอกสารอย่างไร

เอกสาร Living Economy ที่ผู้ใช้ส่งและตรวจพบจริงมี 13 หน้า ลงวันที่ 23 ต.ค. ไม่พบ masterplan 40 หน้า หรือชุด QA 24 กรณี จึงใช้หลักเศรษฐกิจและเหตุผลจากเอกสารเป็นแนวทาง ไม่อ้างว่าครบทุกข้อหรือเป็นสูตรจริงของ CSII

จุดที่คงไว้: 1 วันต่อ tick, 30 วันต่อเดือน, เงินจำนวนเต็มสตางค์, seed, กระเป๋าเงินราย agent, เงินและสินค้ามีคู่บัญชี, ผู้เล่นกำหนดโซนแทนการวางอาคารเอกชน, เงื่อนไขพัฒนาและเหตุผลที่มองเห็นได้

จุดที่ลดเพื่อให้เล่นและตรวจได้ก่อน: 24×24 แทน 64×64, world unit แทน 40 เมตร, โซนติดถนน 1 ช่องแทนระยะ 2 ช่อง, สินค้านามธรรม 1 ชนิดแทน 4 ชนิด, graph reachability แทนต้นทุนเส้นทาง/รถติด และน้ำ/ไฟจากภายนอกแทนเครือข่ายกำลังผลิต รายละเอียดอยู่ใน [DESIGN.md](DESIGN.md)

## ขั้นต่อไปหลัง review

1. แยกวัตถุดิบ อาหาร สินค้าทั่วไป และบริการ พร้อมตรวจสมดุลสินค้าแต่ละชนิด
2. เพิ่มระยะ/ต้นทุนเส้นทาง A* และข้อมูล flow ก่อนทำรถเป็นรายคัน congestion และขนส่งสาธารณะ
3. เพิ่มถนนที่บรรทุกน้ำ/ไฟ เครือข่าย capacity ค่าใช้จ่าย และเหตุผลขาดบริการ
4. ทดสอบขนาด 64×64 ปรับประสิทธิภาพ และเพิ่มความละเอียดถนน/โค้ง/ช่องจราจรตามข้อมูลวัดจริง

ยังไม่รวมบัญชีผู้ใช้ cloud save บริการเสียเงิน หรือการสร้าง Editor account การ deploy เป็นงานแยกหลังอนุมัติ ไม่เกิดจากการเปิด draft PR
